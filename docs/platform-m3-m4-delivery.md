## M3：文本任务与产物

- 新增「文本生成」入口，内置原有 13 步论文流程的可配置副本。选择原始数据集、文本服务、解析/Tokenizer 路径与必要参数后保存。保留原 13 个步骤、五项至少 4 分筛选和问题/答案组合去重，没有重选算法或拆分 PDF 批次。
- 向导与进阶画布共享 PipelineRegistry 和同一个配置 ID。画布保留 `execution_options`，进入和返回时重新读取对应配置；浏览器实际验证保存往返。
- 未绑定服务的配置允许保存；运行检查与提交明确拦截，不写 queued。服务配置、模型/端点/凭据、本地路径及资源引用在提交前检查；检查不调用远端，不能证明远端服务可用。
- 任务复制输入 PDF 和清单并固定哈希；保留 M2 的 Prompt/Schema 内容快照，追加不包含密钥的服务参数快照。原输入变化不改变任务副本，副本损坏会在执行前失败。
- 默认额外重试 0 次，实际传给核心服务 `max_retries=1`；同步与 Ray 两条生产循环验证一致。原 Serving 配置不修改。
- 任务详情包含整批进度、步骤数量、日志、失败原因、配置与输入快照及产物清单。原始响应为算子解析前的模型返回文本，不声称保存了完整 HTTP 报文；候选文件与精简训练文件分别固定。
- 失败/取消批次可手动重跑，新任务保存 `retry_of`，旧任务与产物保留。完整批次核对产物文件和哈希后复用；不支持单 QA 或任意步骤内部恢复。应用中断遗留的 running 任务可终止后整批重跑。
- 修复历史结果读取公共缓存、误回退到其他步骤的问题；已完成任务不再允许终止。任务更新使用跨进程锁、原子写入和按任务合并，损坏历史文件明确报错并保留原文件。

## M4：草稿与版本

- 从已完成任务明确选择训练产物和目标草稿。训练产物只收集 `instruction/input/output`，不混入中间候选、日志或错误对象。重复收集同一任务产物报错；样本内容重复时跳过新增，保留来源关联。
- 草稿保存稳定成员 ID、任务/产物/文件哈希/原行号；支持预览、文本字段编辑、消息 JSON 编辑、删除样本和整批字段映射。非法编辑或映射不部分写入。
- 发布重新验证训练字段、显式图片绑定和图片哈希，固定样本、成员、来源、媒体清单及媒体副本。发布元数据作为提交标志；失败版本不进入发布列表。
- 提供基础 JSONL、符合契约时的 `instruction/input/output` JSONL，以及包含媒体的 ZIP。媒体路径统一改成 `media/<材料ID>.<扩展名>`，同时改写 image/images/消息 image_url，不靠同名文件猜测映射。
- 草稿编辑和原始输出/媒体后续变化不影响旧版本下载。可继续发布下一版本，或从旧版本建立新草稿。图文重建草稿目前要求源材料仍通过校验；旧版本下载使用独立媒体副本。
- 0 条通过筛选仍是正常完成任务，可收集空结果，但空草稿不能发布。任务完成与数据质量通过分别表达。

操作与存储说明见 [文本任务与发布使用说明](../repos/dataflow-webui/docs/text-generation-and-releases.md)。

## 浏览器与下载

1. 保存未绑定服务的临时 13 步配置；检查与提交显示缺少服务，没有创建排队任务。
2. 打开该配置的画布，显示 13 步，执行保存并返回向导；实际 GET 核对同一个 ID、13 步和默认重试选项。
3. 浏览器使用一条明确标注的离线固定样本任务：通过真实 PandasOperator 转存固定输入，没有调用模型，也没有执行真实论文 13 步流程。
4. 在任务详情收集训练产物到文本草稿，再次收集明确报错，没有增加样本。
5. 发布文本 v1 并由浏览器下载 ZIP；编辑回答为空时保存失败，填写合法回答后保存成功。重新下载旧版本，与浏览器第一次下载字节完全一致。
6. 图文草稿导入显式映射的图片与消息，预览并发布 v1。下载包内所有 image_url 都指向实际存在的相对媒体路径，逐文件 SHA-256 与清单一致。
