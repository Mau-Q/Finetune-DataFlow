# 四类 Pipeline 的模型 API

使用者在自己 WebUI 的模型服务管理中配置服务；仓库不提供密钥，也不预绑定个人服务。

| 配置项 | 要求 |
| --- | --- |
| Serving 类型 | `APILLMServing_request` |
| API 地址 | 完整的 OpenAI 兼容聊天端点，例如 `https://api.example.com/v1/chat/completions` |
| 模型名 | 服务商实际提供、账号可访问的模型 ID |
| 密钥 | 在本地 WebUI 按服务配置输入；不写入公开代码、截图或 Issue |
| 图片能力 | 接受 `image_url` 内容块及 base64 data URL |

文本流程可共用一个文本模型服务，图片流程可共用一个视觉语言模型服务；同一多模态端点同时支持两类请求时，也可共用服务。每个 `llm_serving` 参数都必须绑定，包括 DPO 配对节点的负例重试服务。保存配置不会自动替其他节点绑定，也不会试连远端。

| 模板 | 模型调用 | 常规请求规模（未发生重试） |
| --- | --- | --- |
| 文本 SFT | 从原文生成 QA | 每条有效来源约 1 次 |
| 文本 DPO | 生成 QA、同题合成负例 | 每条有效来源约 2 次 |
| 图文 SFT | 看图提问、看图回答 | 每张图约 2 次 |
| 图文 DPO | 看图提问、正例回答、合成负例 | 每张图约 3 次 |

请求数量依赖模型输出、QA 展开及有效来源数量；DPO 相同/无效负例最多额外尝试 2 次。四类代表流程当前均不调用模型评分。格式、非空字段、同题和重复回答检查仍保留。

先以单条文本或一张图试跑，核对原始模型响应与最终文件。无效候选逐条写入 `invalid_samples.jsonl`；全无效时最终文件可为空，且不会自动创建空生成数据集。密钥、服务配置或缺失列等流程级问题仍可能使任务失败。

本地服务注册表位于 WebUI `backend/data/`，可能含敏感配置，不应进入 Git。提交后任务会固定相关资源与非密钥配置；切换服务或修改 Prompt 不会回写历史任务快照。

生成结果中的 `chosen` 表示生成正例角色，`rejected` 表示合成负例角色。负例应有具体事实、数值或条件错误；必须对照原材料确认，不能因字段名称或字符串不同就当成可靠偏好数据。
