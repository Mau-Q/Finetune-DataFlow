# DataFlex 接入设计：固定主机 SSH 训练

日期：2026-10-20。状态：已依确认方向实现 B1–B6 的离线/隔离交付；真实 SSH/GPU 待 G1。依据 ADR 0007–0010。

## 产品与交付边界

面向具备微调基础的独立部署使用者，主要目的是配置、启动和管理模型训练；训练过程中需要调整或自行改造算法与策略，并进行必要的对照比较和评测。DataFlow WebUI 增加模型训练模块，共用已有数据集与发布版本；DataFlex 保持独立源码、环境与进程。对照比较是必要能力，但不是创建一次普通训练的前置条件。

主流程：选定数据 → 创建训练方案 → 配置检查 → 固定运行包 → SSH 上传固定主机 → 环境检查 → 启动训练 → 增量同步结果 → 查看训练状态与模型产物。需要比较时，将多个方案或运行加入实验组并查看条件差异及结果。人工导出、执行与结果导入作为辅助流程，与 SSH 路径使用相同契约。

UI 尽量复用 DataFlow 原生管理页面、导航、表单控件、弹窗、列表/详情布局、明暗主题与编辑保护，图表沿用现有 Chart.js。不为训练模块另建 UI 组件体系；确有缺口时局部补充，保持现有风格与交互。该要求适用于每个实现批次及浏览器验收。

目前没有 GPU：交付前后端配置、检查、打包、SSH 控制逻辑及结果展示；用隔离测试和明确标记的合成夹具验证。未配置主机时允许保存和导出，真实启动明确不可用。离线流程通过不算真实 SSH/CUDA 训练通过。

## 已确认的实验模型

- 训练方案可独立创建、保存和运行，不强制加入实验组；需要比较时，实验组声明共享条件及允许变化的对照因素，静态基线作为可添加方案，不自动启动。
- 实验方案可编辑，运行时生成不可变配置快照；同一方案可按多个种子执行。
- 普通训练按其方案声明的预算执行，不因没有对照预算而被拦截；对照组默认固定优化器更新步数、有效 batch 配置。另外记录 token 数、策略成本与训练耗时，未采集项显示缺失，不用估算冒充实测。
- 实验组显示条件差异，不自动将任意不同模型、数据或预算的运行归为公平对照。
- 导出生成交付记录，不伪造运行。远程启动或外部真实执行产生运行记录，使用独立 attempt ID。

## 数据、源码与模型

- 默认绑定已发布数据版本；可从草稿开始配置，执行前必须明确固定版本。
- 外部文件与 Hugging Face 数据集需固定文件哈希或 revision、子集、划分、字段映射与内容身份；不能固定则标明不可复现，不允许标为完整可复现对照。
- 训练域、验证集、策略目标参考集分别绑定。首期以每域一份或多份明确数据引用表达，不隐式猜测样本领域。
- 固定 train/validation 划分与种子，检查可识别的成员重叠；策略参考集参与策略计算，应在实验中披露，不当作独立测试集。
- 包内生成专用 train.yaml、components.yaml、dataset_info.json，重写到运行目录内路径，不修改仓库全局配置。
- 保存源码快照及哈希、基准 commit 和未提交状态。包含执行所需源码及显式自定义组件，排除密钥、环境、模型、缓存和无关输出；没有 Git 跟踪的组件须显式列入快照。
- 模型权重留在远端或按固定 revision 获取；记录实际模型与 Tokenizer 身份。运行包不包含凭据。
- 预处理索引到 sample_id 的映射单独保存。过滤、切分、packing 改变映射时不得按原始行号推断；首条验证路径关闭 packing。

## 策略覆盖与自定义算法

五类均有入口；文本 SFT 是必验主线，PT、图文 SFT 等按实际兼容矩阵展示，DPO 动态策略不默认开放。逐算法检查配置、依赖、离线产物与额外模型；可通过通用机制低成本覆盖的全部接入，复杂流程明确列为单独适配，不因有 YAML 就宣称可用。

内置与自定义算法使用声明式参数描述：组件标识、类别、参数类型/范围/默认值、必需输入、可用任务模态与依赖。表单和高级配置共用一个方案定义；未知高级参数可保留，但标明未完成语义校验。普通 WebUI 配置读取不导入任意算法 Python。

算法实现仍在独立 DataFlex 源码中开发，源码快照包含描述与实现。组件注册/依赖检查在隔离训练环境进行。Lego 首期提供可验证预设及阶段列表编辑，限制不支持的组合，不做任意连线画布。

检查分三层：结构与参数 → 数据/组件兼容性 → 远程环境就绪。离线可完成前两层中的可判定部分，环境未检查或算法待实机验证分别显示；三层结果不得合并成一个模糊的成功标识。

## 固定主机与执行

首期只有一个活动训练目标，通过后端可用的 SSH config alias、远程工作目录、Python/Conda 环境与可用 GPU 配置定位；复用系统 SSH 和 known_hosts，不在网页接收私钥或关闭主机身份校验。实际部署地址与凭据以后配置，不在设计期连接。

使用系统 ssh/sftp 的参数数组调用；校验并正确引用远端路径与参数，不把任意前端字符串直接拼入远程 shell。远端环境不自动升级或重建，只提供参考依赖、安装说明和只读预检。

每次运行拥有独立远端目录，先上传暂存、校验哈希再发布为可执行输入。启动请求带幂等标识；主机默认一个训练任务并发，首期不建设自动实验矩阵调度。

远端启动小型随包 runner，记录 attempt 身份、主机、PID/进程组、心跳和最终退出状态，独立于 SSH 会话存活；它不是常驻服务。停止核验进程身份并终止进程组，等待退出后才显示 stopped。PID 复用时不得误杀其他任务。

连接丢失时单独显示连接状态，保留最后观测与时间；未确认退出则不写 failed/completed。服务重启后按远端记录核对，不自动重启训练。首期只支持同一方案从头重跑；checkpoint 恢复按算法状态实际支持情况单独开放，绝不把 SSH 重连称为断点续训。

## 结果、评测与持久化

低频轮询并按偏移同步日志和 JSONL 指标，处理最后一条未写完的记录；无需引入 WebSocket。优先适配 DataFlex 已有结构化文件，例如 odm_weights.jsonl；缺失监控用薄适配补充，不修改算法数学逻辑。

轻量结果包包含 run/attempt ID、运行输入清单哈希、实际配置与环境、退出状态、日志、指标、产物清单。checkpoint 默认留远端；路径登记与文件已核验/已下载状态分开。局部运行、失败运行同样可导入，不能因有 loss 曲线就判 completed。

同一 attempt 的相同内容导入幂等；冲突内容不覆盖历史，返回明确冲突。同步中的运行允许按单调序号追加，终态封存；合成夹具标记与真实执行分开，默认不进入真实实验比较。

评测记录绑定 run/attempt、模型产物身份、评测任务/数据版本、指标定义、工具版本与配置。训练指标和评测指标分别展示；当前只定义导入与展示，不选择评测平台，不自动修改数据或触发再训练。

训练元数据采用独立 SQLite 文件，避免把日志、训练状态塞入原数据集库或算子任务 JSON；仅引用发布版本并保存输入清单快照。增量日志与指标作为文件，数据库存索引及身份；备份覆盖本地实验元数据和轻量结果，远端大模型产物不假定已被本地备份。

## 实施与验收顺序

具体批次以 [实施计划](dataflex-implementation-plan.md) 为准：B1–B6 按依赖连续推进，每批同步完成前后端与相应验证并记录进度，无需逐批重新确认。没有真实主机/GPU 时完成 SSH 隔离测试与离线集成，真实连接和训练统一留待 G1 资源就绪后验收；不将待验项计作通过。

1. 算法兼容清单、实验模型、表单与高级配置一致性、数据角色和运行包；验证保存重开与身份固定。
2. 结果/评测包导入、真实与夹具分离、条件差异和监控；验证幂等、冲突、缺失和部分结果。
3. 单主机 SSH 适配、上传校验、启动幂等、进程组停止、断连重连；用隔离传输/进程夹具验证，不访问真实机器。
4. GPU 资源可用后，以小模型验证静态/Random，再验证 ODM、加权、排序、Lego 与其他复杂算法；逐项提升验证状态。

实现主要位于 DataFlow-WebUI；根仓库保存集成说明与版本记录；DataFlex 仅在确有必要时增加指标与runner适配，保持算法实现独立。当前未创建新子模块或修改任何运行配置。
