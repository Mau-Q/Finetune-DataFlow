# 微调数据生成平台：首版实施范围

状态：已完成 DataFlow / DataFlow-MM 可行性调研与最小协议链路验证；尚未开始平台业务实现。真实视觉模型推理与质量仍待联调。

## 目标与完成流程

面向其他使用者交付可独立部署的数据生成平台，先完成基本功能。首版跑通：导入原始材料 → 准备生成输入 → 配置 Prompt、Schema 和模型服务 → 执行 Pipeline → 查看成功与失败结果 → 整理数据集草稿 → 发布固定版本 → 导出训练数据。

文本 SFT 与视觉语言 SFT 均为首版目标。现已验证真实算子、视觉请求、结果文件交换和媒体导出的最小协议链路，不能将其表述为真实模型生成质量已经通过。优先复用当前 WebUI、DataFlow 算子、本地扩展和已有持久化方式，不以本轮设计为由重建整个平台或引入复杂基础设施。未来共享部署、DPO 和训练反馈只作为扩展方向，不实现空壳功能冒充支持。

## 算子复用与执行边界（2026-10-19 调研后更新）

详细结论、兼容性与复现命令见 [DataFlow / MM 调研报告](research/dataflow-mm-compatibility-2026-10-19.md)，完整相关清单见 [源码索引](research/dataflow-vision-source-index.md)。

- 文本路线继续使用当前核心 DataFlow 和本地 MinerU 4 扩展。已用真实单页解析产物执行现有 PageExtractor 和文本生成器；生成响应来自本地测试 API。
- 视觉路线选择 MM API VQA 的原计算逻辑：优先两步图片问答，可扩展动态模板和单图多问题。MM 已放在 `repos/dataflow-mm`，以固定源码和独立进程运行，通过 JSON 交换产物；不将两个同名 `dataflow` 包直接混装。
- 最小 PoC 已执行官方 MM `image_vqa.py` 的 `forward()`，覆盖独立图片、PDF 整页渲染图及真实 MinerU 裁图。已核对图片字节、问题向回答步骤的传递，并在核心进程完成格式转换和媒体打包。
- 待做的平台薄适配包括：服务配置与进程入口、Prompt/Schema 解析和快照、有效图片检查、响应结构验证、失败状态、媒体清单和按记录恢复。当前 WebUI 仅有文本 Serving 的注册与注入，不会自动识别 MM 的 `serving` 参数。
- 首版 Schema 验收包含生成后的本地结构验证。MM messages 接口目前没有 `json_schema` 参数，不能承诺现成服务端严格约束；如后续增加需单独验证。
- PDF2VQA 是题目与答案抽取专用流程，不作为通用资料的默认视觉合成方案。旧内容清单与 MinerU 4 ZIP 不直通；复用已有解析结果时使用明确的图片映射。
- 不把 MM 的 GPU、CLIP、NLI、视觉依赖过滤等高级组件加入基础链路；其中已发现缺失依赖和 API 方法不匹配。

PoC 使用独立解释器入口并借用原环境已有依赖，未向核心环境安装或升级 MM 包，也没有完成 MM 全量独立依赖安装。真实视觉模型调用、质量、Linux/CUDA 和 WebUI 接入仍未验证，平台开发继续暂缓。

## 已确定的模块边界

| 模块 | 首版基本功能 | 当前不做 |
| --- | --- | --- |
| 原始材料管理 | 导入或登记 PDF、图片及承载公式和表格的材料；列表、基础元数据、可用预览、解析产物关联 | 针对未知真实材料开发解析器、复杂修订传播 |
| 材料准备 | 从现有 DataFlow 算子及已安装扩展中核对并复用可用解析能力，保留文件与产物引用；不支持或不可用的能力明确报错 | 保证所有公式、表格和复杂版面准确解析 |
| Prompt 管理 | 独立 CRUD、模板预览、变量检查、供流程引用 | 新建一套 Prompt 类注册语义 |
| Schema 管理 | 独立 CRUD、后端 Schema 有效性检查、输出结构校验、供流程引用 | 用结构校验代替语义质量审核 |
| Pipeline | 向导创建、画布查看和调整同一配置；字段映射；连接用户已配置的远程或本地模型服务 | 自动下载和启动模型、GPU 管理、任意工作流引擎重写 |
| 任务运行 | 状态与进度、成功及失败记录、原始响应引用、按输入记录恢复、手动重跑失败项 | 每个步骤的精细恢复、自动内容修复循环 |
| 生成数据集 | 文本与视觉语言分类；草稿预览和基本编辑；发布版本冻结；训练文件与媒体资源导出 | 完整人工审核工作台、DPO 生成、训练与评测执行 |

公式和表格既可存在于独立材料，也可作为 PDF 或图片中的内容；首版不要求另建复杂的公式或表格编辑系统。

## 解耦的最小验收

1. Prompt 与 Schema 可在没有 Pipeline 的情况下创建和管理。
2. 同一资源可以被多个 Pipeline 引用；Pipeline 保存步骤、绑定和资源引用，不要求复制一份独立管理的资源。
3. 任务启动时固定实际使用的 Prompt、Schema 和流程配置，并保留内容快照或等效的不可变版本及哈希。之后编辑资源不改变历史任务或该任务的恢复输入。
4. 缺失资源、缺少模板变量和不兼容字段绑定在执行前明确失败。旧式内联参数保留兼容，不要求所有旧流程先迁移才能运行。
5. 向导、画布及已有执行路径共用资源解析规则。复用现有 Registry 语义，不改变 DataFlow 核心契约。

## 执行与恢复的最小契约

- 单条生成结果的成功、请求失败、响应解析失败、Schema 校验失败分别可查看，不静默丢弃失败项。
- 有限自动重试可配置，默认额外重试次数为 0；默认允许使用者手动重跑失败项。重试保留尝试记录，不覆盖原始响应。适配不同客户端的次数语义：核心服务的 `max_retries=1` 才表示一次尝试，不能把平台的 0 原样传入；MM SDK 重试也需显式控制。
- 按输入记录保存完成状态。批量任务中断后，保留已完成结果，仅继续未完成或明确选择重跑的记录；恢复使用该任务固定的配置。
- 不承诺外部模型调用恰好一次：请求已发送但结果尚未保存时中断，恢复可能再次调用；结果合并和导出应避免同一尝试重复写入。
- 按阶段保存产物，为未来步骤级恢复提供基础，但首版不实现复杂恢复机制。

## 数据集与未决任务模式

数据集草稿可编辑，发布版本固定；已发布后的修改形成新草稿和新版本。视觉语言数据导出同时保留有效媒体引用或打包资源，避免只有 JSONL 而缺失图片。

“原始材料是否进入最终训练输入”仍未确定。首版通过已有字段映射和导出适配表达训练字段，不把“必须包含全文”或“必须删除上下文”写死。具体任务模板待实现联调时选择可运行示例，不把示例选择升级为产品限制。

最终训练框架及专用导出格式尚未确定。实现时先核对现有可复用导出能力，提供可核验的基础训练文件和媒体清单，不提前开发多个训练框架集成。

## 实施顺序

1. 本轮已验证最小协议链路并确定上述部分复用边界。后续先选定真实视觉服务做小样本联调，再进入平台接入；继续保持真实模型与本地测试 API 的验证状态分开。平台实现开始后先修通 Prompt/Schema 引用和校验。
2. 补齐材料管理与生成数据集管理的基本模型、接口和页面；保持两个管理边界清晰。
3. 串通文本 SFT 最小流程，再串通视觉语言 SFT；向导与画布使用同一配置。
4. 补齐按输入记录恢复、失败重跑、固定版本发布和文件导出，完成端到端验证。

每阶段修改前检查涉及仓库的 Git 状态，保留已有改动；按实际仓库分别提交和验证。

## 验证边界

- 使用小规模演示材料验证导入、解析产物引用、文本和视觉语言生成、结果预览与导出，不声称已验证未知业务材料。
- 通过隔离测试验证非法 Schema、缺失资源、模板变量、运行快照及按输入记录恢复。验证恢复不会重复合并已保存结果。
- 验证发布版本不随草稿编辑变化，视觉语言导出包可解析且引用的图片实际存在。
- 使用模拟模型响应覆盖离线链路与失败分支；真实 API 联调只有在已配置可用服务并获运行授权时执行，明确区分模拟验证与真实调用结果。
- 运行与改动相关的测试；需要较完整回归时使用工作区的 `./scripts/test-local.sh`。页面改动还需浏览器端到端检查。

## 明确暂缓

RAG、军事资料专项适配、真实材料验收、训练和模型交付、模型评测、训练反馈闭环、来源修订影响追踪、完整人工复核系统、多用户共享部署、DPO 生成、精细步骤级恢复。后续需求明确后再决定，不为这些方向提前堆叠实现。
