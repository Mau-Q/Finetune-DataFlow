# ADR 0006：原始与生成数据集统一 SQLite 及备份恢复

- 日期：2026-10-19
- 状态：用户明确授权后实施
- 范围：DataFlow-WebUI 的原始数据集、材料、生成数据集和发布版本

## 背景与决定变化

原实施计划第 31 行明确要求 M1–M6 首版沿用文件持久化，不引入数据库迁移。这是当时的明确范围，不是框架禁止使用数据库。首版已按该边界交付。

用户在检查数据保存后，先要求为 13 篇论文保存受管副本、保护注册表写入、增加自动备份恢复；随后在讨论数据库管理方案后明确要求“实施”。本次后续授权以 SQLite 统一管理上述数据集元数据，替代首版相应的文件持久化实现。其他模块不做全量数据库迁移。

## 结构与权威

- SQLite：原始数据集、成员关联、材料元数据、草稿、样本、媒体绑定、导入记录和发布元数据。
- 磁盘文件：受管 PDF / 图片、兼容清单、任务输入快照和不可变发布包。
- 原 YAML / JSON 元数据保留为一次性迁移输入，不继续作为另一套可写权威。
- 保留所有原有数据集、材料、草稿、样本及发布版本 ID。
- 模态与训练类型独立保存；本地 DPO 导入不代表已实现 DPO 生成或训练。

SQLite 使用事务、外键、WAL 和 FULL synchronous；原件复制、清单、导出文件采用临时文件、fsync 和原子替换。批量材料导入的元数据在一个事务提交。

## 副本、备份和恢复

13 篇论文复制到平台材料目录，保留原 PDF 和原清单，逐份核对哈希。原始数据集 ID 不变，当前清单和数据库关联指向平台副本。

服务启动、成功修改数据集以及运行期间每小时创建一致性备份；使用 SQLite 备份 API，包含受管文件与被登记的外部文件，逐项记录并核验 SHA-256。保留最近 24 份快照，迁移前 baseline 独立保留。

启动时发现数据库或受管数据损坏，先校验恢复副本，再隔离受损现场并恢复。指定快照回退需停止服务，当前数据同样保留为 quarantine。外部原件在备份后发生变化时拒绝覆盖，交人工核对。

历史失效的外部引用记录在备份清单，不凭文件名猜测修复；当前可见的 13 篇论文已全部转为受管副本。本地备份不提供异地灾备，也不将所有运行缓存或开发环境视为数据集备份。

操作及验证见 WebUI 的 `docs/dataset-storage.md`，本轮结果见 `docs/platform-dataset-storage-delivery.md`。
