# DataFlex 面向策略实验，首期交付配置与运行包

2026-10-20，grill-with-docs 第一轮选择了策略比较方向；用户在实施计划阶段进一步澄清，主要目的是模型训练，训练过程中需要调整、自行改造算法与策略，并开展必要比较。以此澄清为当前定位：平台服务模型训练，比较是必要配套能力，不要求普通训练先创建实验组。平台后续还将接入评测并形成反馈闭环，保留训练条件、策略身份和结果可追踪性。

当前没有 GPU 资源，首期交付前后端配置、校验、运行包导出及必要流程，以配置交付作为验收边界，不以网页启动真实 GPU 训练为本期完成条件。配置与离线流程验证不能记为训练或策略效果验证；GPU 资源具备后再验证实际执行。后续各轮逐步明确覆盖、扩展与结果接入边界。

本决定扩展 ADR 0001、0004 中暂缓训练的产品方向，但不在本期实施评测平台或自动数据更新闭环。评测与闭环是已确认的后续目标，其接口、自动化程度及验收条件另行决定。

第二轮已确认：五类策略均提供配置入口，每类优先交付代表性预设与结构化表单，其他算法允许高级配置；若逐项核查后确认额外接入代价不大，则尽量覆盖全部已有算法。完整算法覆盖仍需核查前置输入、额外依赖和配置兼容性，不把通用参数编辑等同于算法已运行验证。

首期包含结果包导入及指标、日志、产物清单展示，以明确标记的合成夹具验证展示与解析；不以模拟执行代替真实训练。运行包、结果包、数据打包和监控字段的具体契约待后续轮次确认。

第三轮已确认：文本 SFT 是必验配置主线，PT、图文 SFT 等现有路径按任务、模态与算法的实际兼容条件开放并标明待验状态；DPO 不因平台支持数据管理而视作动态策略训练已兼容。数据绑定默认使用平台发布版本，同时允许外部文件与 Hugging Face 数据集，需记录角色、版本、配置和哈希，无法固定的输入明确标记。

第四轮用户确认可搬运运行包、参考依赖与环境检查、轻量结果包，以及关联具体运行和模型产物的通用评测导入契约。随后进一步明确主执行路径为 SSH 连接固定机器，后续设计细节委托代理决定。该收敛由 ADR 0010 及接入设计说明具体化；运行包保留为内部交付与手动导出能力，不再以人工搬运作为主要操作流程。当前无 GPU 条件的验收边界不变，尚未授权实现或连接远程机器。
