## 当前实现与已撤销的固定分配

`paper_dataflow.context_selection.propose_contexts` 针对每篇论文：

1. 原有解析质量门先行，排除已知不合格上下文；标题规则排除参考文献/致谢，低于 150 token 的前置信息暂不作为材料，精确重复原文只取一次。这些规则是当前工程启发式，并非论文提出的阈值。
2. 对全部可用块计算论文内 word TF-IDF 余弦矩阵，无联网、嵌入下载或额外商用 API 请求。按照标题规则标记概述、方法、实验、边界四种角色；一个块可有多角色，也可没有。角色只是索引提示，不能证明该块能独立支持对应问题。
3. 离线基线贪心最大化 `mean_j max_i∈S cosine(j,i) + 0.5 × covered_roles / available_roles`，此前实验取至多 4 块，边际增益为零则提前结束。现在 `propose_contexts` 默认仅排序、不设 4 块上限；可选上限只用于离线对照。这里是词汇 facility-location 加角色集合覆盖，**不是原文的语义嵌入 log-det 复现**。该目标具有收益递减性质；任何近似保证只针对这个代理目标，不针对科学正确性或训练收益。
4. `budget_contexts(df, allocations, max_candidates_per_paper=8)` 只执行明确的论文级分配计划，例如 `{doc: {unitA: 1, unitB: 3, unitC: 4}}` 或八个上下文各分 1 条；不再自动用总预算除以每块 2 条得到块数。允许某篇没有可生成任务，分配为空。全部原文与来源仍保留。
5. 每行记录 `generation_sample_budget`。生成提示与 `parse_candidates` 都使用该行额度；超过额度的响应保留原始内容并标为协议错误，不靠截取前几条掩盖超额生成。重复 document/unit 身份和论文计划总额超限直接报错。

当前完成的是可变额度的确定性约束，不是已经实现了最优数量预测器。计划生成器、跨任务累计额度账本和审核后的有条件补充仍需单独接入；纯 DataFrame 变换不能保证跨重跑的实际请求总额。学校端尚未部署这些变化。

## 每篇样本数的新方案：先规划任务，再决定数量

本轮决策为 REFERENCE_ONLY；不安装新训练框架，不引入模型梯度计算。新增核对的方法：

- [InfinityInstruct-Subject / Scaling Towards the Information Boundary of Instructions through Data Synthesizing，AAAI 2026](https://ojs.aaai.org/index.php/AAAI/article/view/40311/)：参考分层任务标签、覆盖和深度缺口导向的定向生成；论文以通用指令数据与模型缺陷诊断为主，不是每篇科学论文的最优数量预测器。
- [Training-Aware Target Coverage for Synthetic Data Selection，arXiv:2610.00814v1，2026-09-30](https://arxiv.org/abs/2610.00814)：参考新增信息价值必须和答案错误代价共同考虑。原实现需要目标模型、真实训练数据与独立带标签 probe；SFT 算法仍使用给定选择预算，因此它不提供可直接套用的“每篇应生成几条”规则。本项目当前没有这些训练信号，不能把词汇/任务覆盖冒充下游收益估计。
- [SciQAG v2，2024-07-10](https://arxiv.org/html/2405.09939v2)：科学论文驱动的生成与评价是可借鉴基础，但其种子阶段使用每篇 10 条，不是经证明的最优样本数；满分自动评价仍不保证事实正确。

ACS 的 OpenReview 正文访问被验证页阻断，仅保留检索线索，未作为决定依据。VRQA 全文受限，未宣称复现。当前没有核验到能直接给本项目每篇论文准确最优条数的公认算法。

建议的工作流：

1. 解析完整论文，建立带页码、章节、表格及邻近解释关系的证据索引。索引不等于全文语义审阅；候选任务必须回查原始证据，不仅靠摘要或标题生成。
2. 先规划简短任务规格，不写完整答案。每个任务绑定 `plan_id`、学习目标、需要的认知操作、证据位置与支持状态。信息不足、仅换一种问法、仅换 JSON 格式的重复计划不占生成额度。
3. 将论文的核心结论、关键方法/条件及支持它们的实验视为需要覆盖的目标，存在性由论文决定，不强制每篇都有固定任务类型。用覆盖增益引导选择，再删除不增加核心目标覆盖的冗余规格；数量是选择结果，最多 8 个。核心目标不能在额度内覆盖时记录缺口，不把“达到 8”描述成覆盖完整。
4. 按计划组装完整原文证据，可一条任务引用多个块，也可一个块支持多个不同任务；请求打包由 token 长度和证据关联决定。所有请求分配之和不得超过本篇剩余额度，不设 4 块或每块 2 条限制。
5. 一次生成已规划任务的答案并审核正确性、证据支持及与已有样本的实质差异。可以少于计划数量，不为达到约 5 条而凑数。仅当核心任务仍有缺口且尚有未使用额度时考虑定向补充，已生成而被拒绝的候选仍占用尝试额度；不自动重试商业调用结果未知的请求。
6. 终止条件是核心学习目标已覆盖、没有新增有价值且证据充分的任务、达到 8 条候选上限，或遇到证据/请求结果不确定。目标约 5 条合格是观察期望，不是停止阈值或必须达到的指标。

样本数可写成 `N_p = |S_p| <= 8`，其中 `S_p` 是本篇经过证据核对和冗余删除的任务规格集合。不是根据页数或分块数线性推算，也不是令所有论文固定输出相同数量。这个方案借鉴覆盖与错误代价原则，具体的核心目标识别、集合覆盖近似与停止判据仍需用独立人工/来源审查校准；不能预先宣称已达到最优。

速度方面，每篇增加规划与核对会有开销。规划应复用已解析材料及已有付费响应，集中处理紧凑任务规格，避免为每个块新增一次规划调用。已有样本先映射至任务清单，覆盖的目标不再生成；新增调用的请求数、token 和耗时必须单独计入。跨论文的独立请求仍可并发，单篇的审核反馈存在依赖。当前没有执行新一轮商业生成来证明速度收益。

## 标准与增强流水线：本轮选用标准版

用户明确：当前测试阶段使用标准版；增强版给出设计，按批分配暂缓。两版共用论文级候选上限、原文证据和三态准入，不以增加成本或模型数量定义质量保证。

| 环节 | 标准版：本轮目标 | 增强版：设计保留，不启用 |
| --- | --- | --- |
| 完整解析 | 复用 MinerU 完整产物及校验缓存 | 相同，必要时增加表格/图片证据核查 |
| 任务规划 | 紧凑论文级任务规格，来源定位；复用现有生成模型，无每块规划调用 | 分层任务规格与跨块证据关系，增加语义核对 |
| 数量决定 | 按核心目标覆盖增益贪心选择、反向删冗余，生成数量由保留规格数决定，最多 8 条 | 语义覆盖与预期有效增益联合选择；仍在同一论文预算内 |
| 材料定位 | 现有结构索引、TF-IDF/关键词；保持原文块完整，匹配不充分则暂缓 | 语义检索与重排，补齐跨块条件、表格注释及上下文 |
| 生成 | Qwen 服务按计划生成；按证据复用及 token 长度打包，不规定块数或每块条数 | 复杂任务可先构造证据链，再生成；不默认增加无关任务 |
| 本地预检 | JSON/schema、额度、ID、精确去重、长度、来源引用有效性；数字/单位不一致只作为风险标记，不能代替语义核验 | 加入可验证的数值关系或符号一致性工具；无法验证的公式转待复核 |
| 模型审核 | 现有独立 DeepSeek 服务批量读问题、完整答案和原文证据，逐样本检查 grounding、task fit、usefulness；重点核对数值、比较方向、限定条件和同篇重复 | 将可核验陈述分解并保留限定条件，逐项定位证据、判断支持/矛盾/不足；仅对争议项补证或独立复核 |
| 处理分歧 | 不自动放行，也不自动触发昂贵多轮复核；保留 REVIEW 待人工/来源复查 | 有限补证与第二审核者复核，意见冲突仍保留 REVIEW |
| 导出 | 仅全部 PASS，保存拒绝、待复核、来源及实际调用/token | 相同，附加陈述级证据和复核轨迹 |

标准流程：完整 PDF → 结构证据索引 → 论文级任务规划 → 低成本覆盖/去重选择并确定 N → 原文材料打包 → 生成 → 确定性预检 → 原文约束的批量审核 → 三态筛选 → 导出。

增强流程：完整 PDF → 分层证据索引 → 语义任务规划及选择 → 跨块证据补齐 → 生成 → 陈述分解 → 逐项证据核验 → 仅疑难项复核 → 三态筛选 → 导出。

“批量审核”表示一次请求可包含同篇的多个样本，不表示采用按批样本额度。请求数由材料长度、证据复用和输出空间决定；不承诺每篇只需一次生成或一次审核。前述流程是待接入的目标设计，可变样本额度已实现；任务规划和新审核机制尚未部署，不能将旧平台流程称为已切换完成。

### 审核算法依据与边界

- [FaStFact，Findings EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.1295/)，§4：借鉴分块处理、减少重复取证与选择性深入核验。原文以通用开放事实核验为主，使用模型内部知识作高置信预验证；本项目的论文特定结论不依据模型自信直接放行，仍以论文原文为证据。
- [FACTS Grounding v2，2025-12-11](https://arxiv.org/html/2512.10791)，§6.2：借鉴 grounding 与是否充分回答请求分开判断，不能通过空泛短答获得高事实性评价。其数据设计排除了专家领域及数学/逻辑推理要求，因此不能宣称它验证了本项目公式和复杂科学推理的可靠性。
- [VeriFastScore v3，2025-10-30](https://arxiv.org/html/2505.16973)：单遍联合提取与核验依赖专门训练的评估模型，论文报告简单 few-shot 商用模型方案存在困难。本项目不下载部署该模型，也不把单次 DeepSeek 审核冒充其复现；仅作为降低逐事实调用开销的研究依据，并保留审核漏检验证。
- [ExpertGenQA，2025-03-04](https://arxiv.org/html/2503.02948)，§6：专业任务评价可能受到表面文风影响。审核必须看实质目标和证据，不因换句话说、加长答案或改变格式增加样本价值。

CiteAudit 的当前公开版本主要核查参考文献是否存在及书目信息一致，不将它误用为“引用的论文一定支持答案”的算法依据。没有因为框架名包含 multi-agent 就引入多代理调用。

本轮验收应包括已知负例：比较方向颠倒、模型/实验设置张冠李戴、数值正确但行列含义错误、遗漏限定条件而过度推广、公式符号变化、无关但流畅、同一知识目标改写。标准与增强使用同一组来源核对标签，比较误放行和待复核比例、实际 token、耗时及每条可用样本成本；不能仅以 PASS 比例高证明质量好。自动审核本身和引用定位都可能出错，保留来源复核；当前未证明增强版优于标准版。

## 验收边界

确定性测试覆盖：避免相同早期段落占满预算、跨论文分别预算、重复 ID 拒绝、原文/来源不变、无有效块时失败，以及选择顺序稳定。下一步质量验证应在同批原文和相同生成/审核模型条件下，比较证据支持、重复率、有效任务差异、通过率和每合格样本调用成本。当前未训练模型，未证明下游收益，也未因本次研究改变解析端并发。
