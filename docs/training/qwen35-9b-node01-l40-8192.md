## 6. 驱动、快速内核与 8192 显存风险

CUDA 12.x 的 minor compatibility 最低驱动范围包含 550，但并不保证所有 CUDA 12.8 特性、PTX/JIT 和扩展都能在该驱动上工作。torch 的 cu128 wheel 带有 CUDA runtime 12.8.57 / NVRTC 12.8.61；宿主驱动不随容器更新。必须在 L40 SM89 上验证实际内核，不根据 `torch.cuda.is_available()` 或 `nvidia-smi` 判断通过。[NVIDIA 兼容说明](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)

不因现有 MinerU/vLLM 镜像中出现 CUDA13，就把 CUDA13 当作训练基础。也不自动升级宿主驱动或注入兼容库；若出现 PTX/driver 不兼容，保留错误并单独评估。

Transformers 5.5.4 的 Qwen3.5 代码在 FLA 与 causal-conv1d 可用时启用快速路径，缺少依赖会回退到 PyTorch。必须检查实际 dispatch，包括 `chunk_gated_delta_rule`、`fused_recurrent_gated_delta_rule`、`causal_conv1d_fn` 及融合 RMSNorm，并完成对应前向/反向正确性检查。包安装成功不等于 dispatch 成功。FLA 与 FlashAttention-2 是不同组件；只装后者不能补齐 DeltaNet 快速路径。

第一版 full-attention 使用 PyTorch SDPA，不额外引入 flash-attn 扩展；需记录实际 SDPA 后端和峰值。`gradient_checkpointing=true`，训练时确认 `use_cache=false`，不使用 `device_map=auto` 作为单卡训练分配策略。

此外，8192 × 248320 的完整 logits 单张量约占 BF16 3.79 GiB / FP32 7.58 GiB。交叉熵转换、激活、未量化 embedding/lm_head、优化器和临时空间都会叠加。这个计算不是峰值显存预测。`train_on_prompt=false` 只屏蔽提示词 loss，不会省掉上下文前向计算。

历史 27B 的四卡 FSDP 2048 张量短测试及快路径验证，不能外推为本次单卡 9B 8192 有效长度通过。单卡若 OOM，先检查内核、显存共用、attention/loss 路径；进一步采用融合/分块交叉熵需验证选定复合模型类和 loss 数值一致性，不自动启用未核查的 Liger 配置。不得静默降低 8192、换模型、改成多卡或截断答案后报成功。

## 8. 数据长度与生成链路对齐

现有 Pipeline 用 Qwen2.5 tokenizer 限制材料 6000 tokens，不是本模型完整样本预算。后续需换成所选 revision 的 processor/tokenizer 和实际训练模板重新统计。

可先把 8192 分配为“材料最多约 5500、答案最多约 2000、指令/模板/余量约 692”，这只是规划比例，不能替代实际渲染后的长度检查。中文字符数不作为长度依据。短样本仍保留，不强行补足 8192。

按论文身份先分 train/validation/test；同篇论文及重复版本不能跨集合泄漏。对每条记录保存 source_id/PDF SHA256、证据片段、模板/模型 revision、输入/答案/完整 tokens、监督 token 数及长度分组。

超长记录重新选择更聚焦的证据或保留长样本层，不能静默截断答案。先完成离线渲染审计，确认输入、完整答案、EOS 和监督 mask 正确，排除图片占位符及非预期 `<think>` 内容。训练与推理必须使用相同非思考模板语义，不能混用默认 thinking prompt。

当前论文来源仅 13 篇，实际每个长度桶样本量需生成后统计。若没有真实长样本，8192 内容验收应明确为未运行；可以在单独技术测试中 padding，但不能把该结果写成有效长内容通过。

离线物料应在可联网的 Linux amd64/CPython3.12 构建环境完成全依赖解析、构建和哈希清单，再传输到学校；不能把 macOS/arm64 下载结果当 Linux GPU wheel。现有 9B 训练环境不存在，旧实验 ready-to-run 镜像已清理的历史记录也不能作为当前安装依据。

平台 host 配置需指向**真正执行训练的 node01**。目前 `school1` 指向 mgt01；不能直接填 school1 就认为在 node01 训练。后续登记独立节点别名/跳板配置，以及训练容器的 Python 包装入口（或固定执行器）。平台 SSHTransport 需要明确 Python 绝对路径；宿主 Conda Python 本身没有容器训练依赖。不得简单把 Docker 容器内路径填成宿主 Python 路径；这项接入在首轮 standalone 验收之后单独验证。

模型服务、MinerU 和训练不并发占用同一张 GPU；训练前协调可用完整 L40，按 UUID 绑定。当前快照没有独占空卡，不选定一个固定卡号长期抢占。容器不挂 Docker socket，不更改主机驱动、网络、防火墙或其他用户容器。

## 10. 后续执行阶段与验收门槛（均待单独授权）

1. **源码适配与物料锁定**：解决 DataFlex 两处声明冲突；完整解析所有依赖；固定模型/框架 commit、基础镜像 digest 和 Linux wheel SHA256；检查所有 DataFlex 对上游内部函数的导入与签名。任何冲突先停止，不跳版本检查。
2. **容器与导入**：独立环境检查 `pip check`，再导入 DataFlex CLI、LLaMA-Factory SFT 入口、processor、正确模型类和量化库；仅包版本或 `pip check` 通过不算训练入口通过。
3. **GPU/内核正确性**：单张获准 L40；核查 SM89、BF16、BNB CUDA、FLA/causal-conv1d 的实际 forward/backward；核对没有回退；CUDA/PTX/ABI 错误保留原始日志后停止。
4. **模型和 adapter**：离线加载完整 checkpoint，确认类、revision、NF4/双重量化、视觉冻结、语言 LoRA 路径；统计总参数/可训练参数和实际 dispatch。没有缺失/意外 adapter key。
5. **短样本训练**：先在 512/2048 范围检查真实监督、有限 loss/梯度、至少两次 optimizer update 和参数变化，不报为 8192 能力。
6. **4096/8192 有效内容**：从真实训练数据长度桶中选包含有效论文材料和答案的长记录，记录完整有效长度/监督长度。逐级完成前向、反向、梯度累积、至少两次 optimizer update。验证 8192 附近真实内容；padding 结果另表保存。
7. **峰值与稳定性**：同时记录 torch peak allocated/reserved 与 nvidia-smi 峰值，区分首轮 JIT 和稳态；记录耗时、吞吐和主机 RAM。建议验收时仍留至少约 4 GiB 显存余量作为运维目标；不足时记录为未达标，不暗改目标。随后用计划的长短混合批次做至少 50 个 optimizer steps 稳定性测试。
8. **评测/保存/恢复**：独立检查 eval loss 和生成评测峰值；保存 adapter、tokenizer/processor、配置和基础 revision；恢复 optimizer/训练步数后继续一步，确认 adapter 正确激活。不能以输出相同或进程退出 0 代替 adapter 生效证据。
9. **平台端到端**：再验证运行包校验、node01 目标、训练 Python/容器入口、提交/状态同步/停止/结果收录；真实 SSH 成功不代表训练已可用。

只有以上对应门槛通过，才能将“8192 单卡环境准备方案”升级为“单卡 8192 实测通过”。完整训练轮数/token 预算和正式发布仍由后续数据规模与验收结果决定。
