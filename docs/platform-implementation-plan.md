# 数据生成平台实施计划

日期：2026-10-19。状态：M1–M4 已实现并完成本地验证；M3 真实小 PDF / 模型试跑待验；M5、M6 最终集成尚未完成。本文是当前实施顺序与验收范围的入口；历史调研结果见 [DataFlow / MM 报告](research/dataflow-mm-compatibility-2026-10-19.md)。

## 1. 本次固定的范围

- 在现有单用户 WebUI 上补齐共用框架，每位使用者独立部署。
- 文本线以已有 [13 算子配置](../pipelines/sft-reading-13.webui.json) 为基线，复用既有 PDF → 清洗 → QA → 评价筛选 → 去重 → SFT 整理流程，不重新选择生成算法。旧 SFT2000 保留。
- 多模态线选择 MM [基础图片 VQA](../repos/dataflow-mm/dataflow/statics/pipelines/api_pipelines/image_vqa.py) 为代表性模板。当前没有可用视觉服务，因此首版搭好模板和配置，不以真实运行成功作为本轮验收条件，也不为此部署本地视觉模型。
- 原始材料管理、Prompt/Schema、任务记录、生成数据集、版本发布和导出共用。材料准备继续作为文本完整流程中的步骤，以及可复用的公共能力，不强制改成独立第三条业务 Pipeline。
- 先完成基本功能；多模态策略、最终训练框架和最终模型交付均不在当前规划中定死。

## 2. 系统结构与修改归属

```text
原始材料管理 ──────┐
Prompt / Schema ───┼→ Pipeline 配置 → 任务运行 → 产物清单 → 数据集草稿 → 发布与导出
模型服务配置 ──────┘       │
                          ├─ 文本：已有 13 算子流程
                          └─ 多模态：MM 图片 VQA 模板，当前未绑定视觉服务
```

| 仓库或目录 | 计划中的职责 |
| --- | --- |
| `repos/dataflow-webui` | 新增或扩展材料、数据集、Prompt/Schema、模板和任务相关服务、API、页面与测试；主要实现位置 |
| 工作区根目录 | 保存接入配置、必要的薄适配脚本、计划、部署与验收记录 |
| `extensions/paper-dataflow` | 继续提供现有 PDF 准备算子；仅在确认必须时做小范围接入调整 |
| `repos/dataflow` | 保留现有算子实现；不以框架建设为由重写生成和评分逻辑 |
| `repos/dataflow-mm` | 固定的独立参考与运行源码；当前不改、不混装到核心环境 |

优先沿用服务容器、API 响应封装、文件持久化和现有执行器，不为首版引入数据库迁移、消息队列、账号系统或通用插件平台。新增元数据需使用明确结构与原子写入；运行产物放独立目录。若现有存储无法满足一个已证实的具体需求，再局部调整。

## 3. 开始实现前的准备

1. 检查工作区及各独立仓库 Git 状态，记录当前提交和变更清单。原有 `pipelines/SFT-PIPELINE-OPERATORS.md` 删除不属于本次变更。
2. 清点相关注册数据与配置，备份将涉及的运行元数据。保留已有数据集、Pipeline、Serving 和历史缓存，不执行清空或全量覆盖注册。
3. 核对 13 算子配置、扩展、Tokenizer、路径及文本服务绑定的当前可用性；历史运行成功不等于当前端点仍可用。不得打印密钥。
4. 固定两份平台模板标识和职责：已有文本流程副本、MM 基础图片 VQA 模板。接入任务使用新配置副本，不直接覆盖旧实验配置、Prompt 或历史结果。
5. 每个受影响仓库分别建立实现分支与提交；不把其他仓库的改动混入工作区提交。

这一步只做实施准备，不重新初始化 Git 或重建已有开发环境。

## 4. 分阶段实施

### M1：材料与数据集的基础管理

**交付**

- 原始材料入口：导入或登记、分组、列表、详情、可用预览、来源与解析产物关联。第一批支持 PDF 和常见图片；公式和表格先通过原文件或已有解析产物管理，不开发专门编辑器。
- 生成数据集入口：创建草稿、导入已有 JSON/JSONL、字段预览与文本/图文分类。字段不合规、媒体缺失和重复导入应有明确提示。
- 模态和训练类型分别保存；当前提供文本/图文与 SFT，DPO 只保留扩展位置，不显示为已支持生成的功能。
- 新增独立的材料与训练数据集元数据边界；现有 `DatasetRegistry` 继续承担旧流程文件输入和兼容登记，不要求一次迁移所有旧记录。

**主要接入位置**：`backend/app/services`、`schemas`、`api/v1/endpoints`、`core/container.py`；前端管理路由、导航与对应页面。

**验收**：上传一个 PDF 和一张图片后可查看且刷新不丢失；导入一份已有训练文件能形成草稿并预览；同名文件不会悄悄覆盖另一个文件；旧数据集和 Pipeline 入口继续可用。

### M2：Prompt / Schema 独立管理与引用

**交付**

- 在现有管理功能上补齐模板变量检查、JSON 花括号处理、后端标准 Schema 校验和统一的资源引用解析。
- Pipeline 只保存资源引用与字段绑定；任务启动时固定实际内容及哈希，供历史查看与后续恢复使用。
- 内置 Prompt 保持原类实现和默认行为；自定义模板只接入具备相应参数契约的步骤。对不支持自定义的步骤明确提示，不强制将整条旧流程改造成字符串模板。
- Schema 用于声明结构输出的步骤或整理后的样本；旧 13 算子中的专用 QA、评分协议保持兼容，不把所有步骤强制改为任意 JSON 输出。
- 删除或归档资源不能破坏已经固定的任务快照；缺失引用在提交运行前报错。

**主要接入位置**：`json_schema_manager.py`、`user_prompt_registry.py`、`param_coercion.py`、现有参数面板及两个执行路径的共用解析入口。

**验收**：无 Pipeline 时可以管理资源；两份配置能引用同一模板；无效 Schema 与缺少变量能拦截；资源修改不改变已保存的任务快照；旧内联配置和默认内置提示词行为不变。

### M3：接入既有文本 Pipeline 与任务记录

**交付**

- 文本生成向导：选择材料、现有模板、服务与必要参数，提交到原有执行器。现有 13 个步骤和筛选门槛保持不变。
- 向导和进阶画布读写同一配置，避免来回编辑导致两套配置分叉。
- 任务详情显示输入、配置快照、进度、日志、输出文件及失败原因；将原始响应、候选结果和可导出训练文件分别列入产物清单。
- 沿用已有 queued/running/completed/failed/cancelled 任务状态；模板缺少服务属于运行条件未满足，不伪造为已经排队的任务。
- 提供失败项手动重跑；平台默认额外重试 0 次，适配核心服务“max_retries 包含首次尝试”的实际语义。
- 首版以已完整完成且产物落盘的执行单元恢复，优先将可独立处理的原始材料作为单元，避免重复合并。中断单元允许重新执行原流程，不做单条 QA 或步骤内部恢复；不能仅凭 PDF 已解析就标记整条材料生成已完成。

**边界**：若将多份 PDF 拆成独立执行单元，必须先核对批次级去重和筛选语义，并在合并时保持相同规则；不能确认等价时保留原批次执行边界，不为恢复改写生成算法。对原生整批任务只承诺完整批次的复用和失败重跑，不能宣称任意半途记录均可恢复。进度需注明单位是材料、批次还是样本；独立单元失败不删除其他已完成单元的产物。

**验收**：离线夹具验证任务到产物的连接、失败记录、快照和恢复；有可用文本服务且执行已获授权时，以一个小 PDF 做真实试跑，不重跑整批论文。0 条通过筛选是可表达的完成结果，不伪装为请求失败；任务完成也不等于数据质量通过。

### M4：数据集草稿、发布和导出

**交付**

- 将 M3 的训练产物明确收集到某个数据集草稿，保留来源任务与样本标识；不自动将全部日志和失败记录混入训练数据。
- 草稿支持预览、基础编辑、删除样本和字段映射；不建设完整人工审核工作台。
- 发布时固定数据内容、成员和必要媒体的快照及清单；原始输出文件后来变化也不能改变已发布版本。修改发布内容形成新草稿和新版本。
- 文本先提供现有 `instruction/input/output` 对应导出与基础 JSONL；图文提供消息与媒体清单的导入、管理和打包，即使当前没有视觉生成服务也可使用。
- 媒体使用明确来源映射和有效路径，不以目录中的同名文件猜测对应关系。导出包使用可移植路径并检查图片存在性。

**验收**：文本任务产物能够进入草稿并发布、下载；已有图文样本可以导入和打包；发布后编辑草稿不会改变旧下载内容；缺失图片或无效训练字段会阻止发布或导出并给出原因；重复收集同一运行产物不会悄悄复制样本。

### M5：配置代表性多模态模板

**交付**

- 提供“图片 → 生成问题 → 图片与问题 → 生成答案 → 结构检查与训练格式整理”的 MM 模板。两步提示词分别定义问题与答案，不照搬含糊的同一问答指令。
- 图片来自材料管理，输出指向共用的数据集产物契约。PDF 页面图和解析裁图以后也可作为图片输入；本阶段不额外实现复杂裁图策略。
- 保存模板的步骤、关键参数、Prompt/Schema 引用、输入输出绑定和布局，支持查看与配置。外部 MM 步骤用模板元数据表达，不向核心算子注册表伪注册不存在的类，也不依赖同进程导入两套包。
- 区分配置结构检查和运行条件检查：服务为空时仍能保存草稿，但不能提交运行；明确显示“未配置视觉服务，未做真实运行验证”。
- 模板配置与展示共享同一份数据；现有核心执行器不承担 MM 执行。未来实际启用时，经已调研的独立进程与 JSON 文件边界接入。

**验收**：图片选择、步骤展示、参数编辑、保存与重开、输出绑定和缺少服务的运行拦截可验证。已有 PoC 证明接口可行，不计为本次真实模型验收。不下载大模型、不搭 GPU、不安装 MM 全量依赖，也不重复做本地测试 API 试跑来声称真实视觉流程已跑通。

M5 不阻塞 M1–M4。未来如果获得现成可用视觉 API，且小样本试跑代价很小，再单独联调；目前没有这个前提。

### M6：集成回归与交付说明

**交付与验收**

- 浏览器验证“材料导入 → 文本任务配置 → 产物收集 → 草稿 → 发布与导出”的通路；真实调用与离线夹具验证分别标注。
- 浏览器验证多模态模板可配置、刷新不丢失、无视觉服务不能发起任务。
- 验证向导与画布的配置一致、旧流程可打开、历史记录可访问、资源编辑不改变历史快照。
- 运行相关后端测试和前端构建；做较完整回归时使用 `./scripts/test-local.sh`。修复本次引入的失败，并记录环境或外部服务造成的不可验证项。
- 补充启动、持久化目录、模板使用、导入导出、失败重跑与备份说明。当前按单用户独立部署，不引入共享部署权限功能。
- 各仓库分别检查 diff、提交并记录版本；没有改动的核心与 MM 仓库不制造提交。

## 5. 优先级与完成判定

| 优先级 | 范围 | 完成标志 |
| --- | --- | --- |
| 主线 | M1 → M2 → M3 → M4 | 现有文本生成流程接入共用管理框架，材料和数据集均可独立使用 |
| 配套 | M5，依赖材料和资源契约 | 一份完整可配置的多模态模板，真实运行状态准确标记 |
| 收尾 | M6，覆盖两条线 | 可复现的验证记录、可交付的使用说明与分别提交的源码 |

首版可以宣称：材料与数据集管理基本可用；文本流程已接入；多模态代表性模板已配置。只有实际进行了真实调用，才增加对应的真实运行结论；没有可用文本服务时同样明确保留真实文本运行的待验状态，不以历史报告或夹具冒充。
