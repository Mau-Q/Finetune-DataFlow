# 局域网团队使用

本入口为本地或局域网小团队部署。不要把旧版 `app.main` 直接监听在局域网或公网；团队共享入口是认证网关 `app.team_gateway`。Agent 聊天、Agent 进程和 MCP 产品入口已移除。

## 首次初始化

先停止旧单用户服务，确认没有生成/训练活动任务；备份 `backend/data`、受管材料和外部引用。根目录执行：

```sh
./scripts/start-lan.sh init --name 你的管理员账号
```

命令在主机终端用 getpass 提示两次输入至少 12 字符密码。没有通用默认密码，不接受命令行密码，也没有 HTTP 抢注管理员入口。仅首次可执行。原有业务 ID、文件和内容不重建；原目录被登记为默认项目，初始仅管理员拥有成员资格。无明确创建者的旧记录属于历史导入。

```sh
./scripts/start-lan.sh start
```

后端仅在 `127.0.0.1:8001`，前后端同源。默认 Cookie 为 Secure，实际共享使用下一节 HTTPS。仅在主机本地查看和调试时，可显式设置 `DATAFLOW_COOKIE_SECURE=0`；不要用于局域网明文登录。

## 内网 HTTPS

本机未自动安装 Caddy、修改 DNS、证书信任、防火墙、路由或公网映射。仓库提供 `deploy/Caddyfile.lan`。在已安装 Caddy 的主机配置：

```sh
export DATAFLOW_LAN_HOST=dataflow.internal
export DATAFLOW_LAN_IP=192.168.1.20  # 换成服务主机实际的私网 IP
caddy validate --config deploy/Caddyfile.lan --adapter caddyfile
caddy run --config deploy/Caddyfile.lan --adapter caddyfile
```

让局域网客户端通过内网 DNS 或 hosts 将该名称解析到此私网地址，按组织现有方式信任 Caddy 内部 CA 的根证书，然后访问 `https://dataflow.internal`。共享前确认浏览器信任证书、Cookie 的 Secure 属性、写操作同源检查和其他设备登录。反代的 Host 与 Origin 必须一致，不能添加跨域放行。Caddy 所监听的接口应为私网接口，不配置公网转发。未装 Caddy或没有第二台设备时，内网 TLS 与跨设备验收应明确记录 NOT_RUN。

## 成员与项目

管理员在“协作与人工评测 → 团队设置”创建账号并取得限时一次性邀请码，手动交付给成员。成员在登录页展开“接受邀请”设置自己的密码。管理员为账号分配项目管理、开发和评测权限，可组合。项目开发是受信任的代码执行权限，不是 Python 沙箱；仅评测成员没有代码、服务、主机路径、发布或导出权限。

管理员创建项目后，初始只自己有权限。项目管理者在项目成员表中选择账号及角色。清空角色会立即撤销项目访问，旧下载链接每次仍需认证。退出、禁用、密码重置和修改密码撤销相应会话。系统管理员不自动获得其他项目资源，须显式成为成员；管理动作保留审计。

原始文件使用浏览器上传或拖放。团队模式不提供服务器本机选择器、任意路径登记、Agent、WebSocket、MCP 或主机数据库入口。每个项目后台使用独立受管目录及私有 Unix socket。工作进程退出后由下一次访问重启；初次初始化仅复制已安装的无凭据 Core 模板，不联网下载模型。

## 人工评测与导出

1. 原始数据集“生成情况”列或协作页查看关联任务、收集成果、旧输入提示与发布版本；覆盖率未知时不会用样本数替代。
2. 在生成数据集列表/详情点击“人工评测”，选择草稿/发布版本、全量或随机数量、种子、评分模板及允许评测成员。
3. 评测者领取后，对照样本与可验证来源，评分并选择通过、需修改或拒绝；无法判断需填原因。保存进度、跳过不会计为已提交。
4. “修改并通过”固定新修订、原因与原文。当前草稿已经变化时整笔冲突；发布版本从不覆盖。通过样本可整理为新草稿再显式发布。
5. “导出”先选择来源、批次筛选、格式与字段映射，检查兼容数量和排除字段后创建固定快照。空结果、旧修订冲突或格式不兼容不静默跳过。
6. 图文推荐 ZIP；包内包含数据、媒体和 manifest。原始 JSONL 保留业务字段；Alpaca、messages、DPO 只映射已有字段。评测 CSV/JSONL 单独导出。

导出、发布和人工评测均不执行模型、训练、SSH 或下载。服务重启后批次、评语、来源与导出记录保留。个人语言与主题不会修改其他人的偏好。保存冲突后需重新读取当前对象，保留自己的待提交文本再比较。

## 备份与恢复

本轮迁移前的一致性备份清单和恢复验证见实施证据记录。备份可能含凭据，保存在用户私有目录，不能提交或公开分享。恢复应先停止网关与其子进程，在独立目录恢复并检查数据库及文件哈希，再按清单恢复原路径。禁止用示例重建替代恢复。

项目数据位于原 backend 或 `backend/data/collaboration/projects/<project_id>`；账号与成员保存在 `backend/data/collaboration/team.sqlite3`。默认保留导出文件，不自动清理原始材料、发布版本或人工评测记录。临时开发夹具与验证服务会在收尾删除，恢复备份与验收证据保留。
