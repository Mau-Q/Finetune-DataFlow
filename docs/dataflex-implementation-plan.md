# DataFlex 接入分批实施计划

日期：2026-10-20。状态：B1–B6 已在离线/隔离边界内实现并验收；真实 SSH/GPU 的 G1 待资源就绪。

## 目标与固定边界

主要目的是模型训练：在现有 DataFlow WebUI 中配置训练、通过 SSH 在固定 GPU 主机启动和管理 DataFlex、查看训练状态及模型产物。调整/改造算法、对照比较和评测是必要配套能力，普通训练不强制建立实验组。

当前没有 GPU 资源。先完成前后端配置、运行包、结果展示与 SSH 流程，用隔离测试及合成夹具验证；真实主机 SSH 联调和 GPU 训练按具备条件后分别验收。导出成功、模拟进程完成或合成曲线均不能记为真实训练成功。

以 [接入设计](dataflex-integration-design.md)、[术语](../CONTEXT.md)、ADR 0007–0010 为设计依据；本计划将实施顺序细化为六批及一个资源就绪后的验收批。每批完成后更新本文件，记录改动、检查、限制与涉及仓库版本；不因批次结束重复索取已授权范围的许可。

## Web UI 随批交付与验收

每个实现批次同时交付相应的后端接口、前端页面和浏览器可验证流程，不采用后端先全部完成、最后集中补 UI 的方式。B6 是跨模块集成验收，不是页面开发的起点。

| 批次 | 页面与交互交付 | 本批浏览器验收 |
| --- | --- | --- |
| B1 | 模型训练导航、方案列表/编辑页、模型与数据选择、基础训练参数、可选实验组 | 创建普通方案无需实验组；保存、刷新、重开一致；并发编辑与未保存修改有明确处理 |
| B2 | 五类策略配置、算法参数表单、Lego 阶段列表、高级配置及 YAML 预览、分层检查结果 | 策略切换与高级编辑不静默丢配置；保存重开一致；错误定位到对应字段或阶段 |
| B3 | 运行包生成/下载、文件清单、源码与数据身份、打包状态及失败原因 | 从已保存方案生成并下载包；展示实际清单与待准备条件；失败后可修正并重试 |
| B4 | 运行列表/详情、结果包导入、日志、训练与策略曲线、产物列表、比较页、评测记录 | 导入标记夹具并查看曲线；缺失指标/失败/部分结果准确展示；冲突拒绝；比较显示条件差异 |
| B5 | 固定主机设置、连接/环境检查、启动/停止、连接状态、同步进度 | 未配置主机时保存/导出可用且不能启动；隔离控制测试覆盖重复启动、断连/重连与停止状态 |
| B6 | 页面间完整导航与一致性、旧功能回归、交付说明 | 跨批流程、刷新重开、错误恢复、下载与旧数据生成/发布流程完整回归 |

UI 尽量使用 DataFlow 原生实现：优先复用现有管理页布局、导航、工具栏、表单控件、选择器、弹窗、列表/详情模式、主题与编辑保护；图表沿用现有 Chart.js 基础。实现前核对现有组件的真实接口，不为训练模块另引入一套 UI 组件库或独立视觉体系。现有组件不满足需求时做局部扩展或补充，并遵循原生样式和交互。Lego 首期继续使用原生表单及阶段列表，不新增画布；以后确需画布时优先复用现有 Vue Flow 基础。

各批浏览器验收同时核对与既有页面的一致性，包括明暗主题、布局、控件尺寸、错误与加载状态、未保存修改保护和窄屏表现。页面只呈现当前已实现的动作。B5 之前不提供看似可执行的训练启动按钮；B5 可测试控制流程，但真实主机/GPU 未验收时明确显示状态。开发夹具与隔离传输替身不作为正式用户的训练执行模式。

各批以实际浏览器操作检查对应界面并记录证据，配合相关前端契约测试和构建；后端测试通过不能替代页面验收。浏览器因环境原因无法验收时明确记为待验，不把该批宣称为前后端完整验收完成。无 GPU 的页面验证不包括真实训练效果。

## B1：训练工作区与数据基础

**交付**

- 新增“模型训练”导航及方案列表/编辑入口，普通训练方案无需实验组即可保存。
- 训练方案保存模型和 Tokenizer 引用、训练任务/模态、LoRA/全参选择、预算、种子、数据角色等；缺少运行条件时允许保存草稿并列出待补项。
- 数据选择复用平台已发布版本；外部文件与 Hugging Face 数据引用进入统一数据绑定结构。配置保存阶段不隐式下载模型或大数据。
- 训练域、验证集、策略目标参考集分别绑定；数据草稿到发布版本的转换明确展示，不静默发布。
- 实验组可选，支持加入方案与条件差异；只建立最小的比较基础，不抢先实现运行调度。
- 独立训练 SQLite、API Schema、版本/并发编辑冲突保护、方案复制与重开。预先固定运行/结果包的 v1 身份字段和版本规则，供后续批次共用。

**验收**

保存、刷新、重开后配置一致；过期编辑不能覆盖新版本；普通方案无需对照信息；平台数据绑定不修改原数据；原生成任务和数据页可继续使用。对缺失、损坏的训练存储明确报错，不初始化空库冒充历史状态。

## B2：五类策略、算法清单与配置编译

**交付**

- 逐项核对 DataFlex 当前源码和示例，建立任务 × 模态 × 算法兼容清单，列出额外模型、离线产物、依赖与适配成本；清单包含代码版本及验证层级。
- 静态训练及 Selection/Mixture/Reweighting/Reorder/Lego 均提供入口；每类先有代表性结构化表单。可通过通用描述覆盖的已有算法一并接入，复杂算法明确缺口与适配状态。
- 自定义组件采用声明式参数描述，支持类型、范围、默认值、输入要求和依赖；不在 WebUI 服务进程导入任意算法实现。
- 表单与高级配置读写同一方案，生成运行专用 train.yaml、components.yaml、dataset_info.json；不覆写 DataFlex 全局配置。
- Lego 提供合法预设和阶段列表，执行组合兼容检查；首期不做任意连线画布。
- 参数结构、数据兼容、环境就绪分层显示；PT/图文按证据开放，DPO 动态训练不因数据可导入而默认支持。

**验收**

五类配置均可保存、重开与生成；表单/高级编辑往返不丢字段；缺少参考集、比例非法、组件不存在或 Lego 不兼容有具体错误；自定义示例描述无需修改前端即可生成参数入口。区分“可编辑”“静态检查通过”“待环境验证”。

## B3：运行包、可复现输入与离线环境流程

**交付**

- 导出包包含方案快照、配置、清单、数据/媒体、源码快照、环境检查及启动入口，所有包内引用可搬运。
- 平台发布版本和外部文件核验内容；HF 引用固定 revision/子集/split 等，并在执行前完成所需获取和核验。无法固定者标记限制。
- 数据默认随包，模型权重留远端或使用固定引用；大数据允许显式引用模式并附执行前检查。
- 保存 commit、未提交状态、实际源码和显式自定义组件哈希；排除凭据、缓存、环境及无关文件。
- 参考依赖与实际版本记录、模型与数据预检；不隐式安装或升级远端环境。
- 输入发布到运行目录前核验；生成的数据索引与 sample_id 映射记录清楚，不能准确映射时不猜测。

**验收**

移动到隔离目录可解析包内配置；源码/数据变化产生不同身份；缺失引用或哈希错误阻止执行；导出不创建虚假训练成功记录；不访问真实模型服务、不下载大模型。压缩包路径、符号链接与输入文件类型有明确处理，避免导出无关内容或解包越界。

## B4：结果、监控、比较与评测记录

**交付**

- 导入轻量结果包，关联运行/attempt 和输入清单；保留实际配置、环境、退出状态、日志、指标及模型产物清单。
- 训练详情展示状态、loss、学习率、步数及实际提供的资源/耗时指标；五类策略按可采集信号提供对应视图。
- 优先适配 ODM 等已有结构化文件；缺失指标显示未提供，必要时增加薄指标适配，保持算法逻辑不变。
- 对照显示模型、数据、预算、种子和源码差异；默认 step/batch 对照，不宣称相同步数等于相同成本。
- 结果导入幂等、冲突拒绝、增量追加及终态封存；失败和部分结果可保留。合成夹具单独标记，不混入真实比较。
- 评测导入绑定运行与模型产物，保存任务、数据版本、指标定义和工具/配置身份；不接特定评测调度，不自动驱动数据更新。
- 本地训练元数据与轻量结果备份/恢复单独纳入覆盖；远端 checkpoint 只登记时不宣称已备份。

**验收**

同一结果重复导入不重复创建；身份冲突不能覆盖旧记录；未结束或失败任务不被曲线误判成功；半条 JSONL 与缺失指标可处理；产物登记位置和可下载文件有区别；评测必须关联正确产物。用明确标记夹具完成浏览器展示验证。

## B5：固定主机 SSH 训练流程

**交付**

- 一个活动训练目标：SSH alias、工作目录、Python/Conda 与 GPU 配置，复用系统认证与 known_hosts。
- SSH/SFTP 连接、暂存上传、远端哈希核验、环境预检、运行启动；默认一次一个训练任务，不建设集群调度。
- 随包 runner 脱离连接存活，记录 run/attempt、PID/进程组、心跳与退出状态；启动幂等，避免重复运行。
- 停止核对进程身份并终止进程组，确认退出才标记停止；断线只影响连接状态，不误判训练失败。
- 后端重启后核对远端状态，增量同步日志/指标/产物清单；读取结果与 B4 共用解析链路。
- 从头重跑创建新 attempt；checkpoint 恢复只对明确验证的组合开放。

**验收**

隔离传输替身与真实本地子进程验证上传校验失败、重复点击、连接断开、重连、停止子进程、PID 身份不符及服务恢复。命令参数/远端引用有专门检查，不关闭 SSH 主机校验；未配置机器时保存/导出可用，远程启动明确不可用。

这些检查只证明控制逻辑与隔离进程行为。真实 SSH/SFTP 的兼容性和远端 Linux 进程行为属于 G1；没有真实连接时不能写成“SSH 实机联调通过”。

## B6：集成验收与交付

**交付**

- 浏览器走通独立方案、五类配置、数据版本绑定、打包、夹具结果、比较、评测导入和 SSH 未就绪提示。
- 检查未保存修改、刷新重开、并发编辑、错误提示与文件下载；保留旧数据生成、向导/画布、收集、发布与下载流程。
- 后端相关测试、前端 Node 契约测试、前端构建、git diff --check，以及完整 ./scripts/test-local.sh。
- 验证训练元数据/结果的备份恢复，并核对现有数据集/发布文件保持；实施前对涉及的现有持久化数据创建可核验备份。
- 提供固定主机配置、环境准备、算法扩展、打包/导入、指标和已知限制说明；各仓库分别记录版本，不顺带提交无关改动。

**验收**

形成一份交付记录，分别列出静态/离线、隔离进程、浏览器、真实 SSH、真实 GPU 的验证状态；后两项在资源不可用时明确待验。所有缺口有对应位置与下一步，不用合成成功掩盖缺口。

## G1：资源就绪后的真实验收

先核对主机、依赖、数据、模型、显存和运行预算，完成真实 SSH/SFTP 预检。用小模型及小数据完成静态/Random，再逐项验证 ODM、加权、排序与 Lego，最后处理额外依赖及多阶段算法。检查真实停止、SSH 断连持续运行、重连同步及产物身份。每种算法只按自身实际证据升级验证状态，不以一个算法成功推断全部成功。

真实模型下载、训练预算及可用目标机器在资源就绪时据实际配置确认，不在当前计划中虚构。评测调度与自动闭环后续另立实施范围，不阻塞 B1–B6。

## 仓库归属与执行纪律

- DataFlow-WebUI：主要前后端、训练存储、运行包/结果服务、SSH 控制与测试。
- DataFlow 集成根仓库：本计划、设计、部署/版本记录、必要集成脚本。
- DataFlex：保持独立，确有缺口时增加薄指标/运行适配；逐项说明是否需要改源码。
- 不更改 DataFlow 核心或 MM 的算法、包依赖与注册语义；不把训练 Python 环境混装进生成环境。
- 开始实现前检查状态并建立各涉及仓库的实现分支，保留原有删除和未提交文档；不使用全仓 git add -A。
- 当前不连接真实远端、不安装训练依赖；已有数据只读，训练元数据独立保存。
