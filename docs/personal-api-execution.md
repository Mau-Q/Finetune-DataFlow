# 个人电脑执行商业 API

本次接入复用现有平台账号、项目权限、Serving 配置和 Pipeline 的 Serving ID 绑定。学校继续执行解析、算子与产物管理；只有 APILLMServing_request 的 HTTP 请求经持久化队列交给提交者自己的电脑。Core 算子、模型响应解析和提示词协议保持原有实现。

## 使用入口

在现有 Serving 页面新增或编辑服务：

- API 执行位置：选择“我的电脑”。保存时由后端绑定当前登录用户，其他成员不能查看、修改、测试或执行此个人服务。项目开发成员可创建自己的个人服务，服务器服务仍需项目管理权限。
- 地址、模型、Key：继续使用当前表单。将自己原有的服务改为个人执行时，不需要再次输入未变化的 Key。
- 个人执行模式：默认“模拟验证”。服务标为真实调用且执行器带 `--execute` 时，才允许领取真实请求。模拟与真实队列分开。

个人服务仍按项目保存于原 Serving 注册文件；本次不是本机独占密钥存储。真实执行时通过经验证的 HTTPS 登录会话将该服务的 Key 交给其所有者的执行器，模拟模式不下发 Key。Key 不进入队列、执行器结果缓存或命令行。系统管理员仍可管理服务器文件，这不是对主机管理员的密钥隔离。

## Mac / Windows 执行器

需要 Python 3.10 或更新版本。执行器仅使用 Python 标准库，无须安装 DataFlow、PyTorch 或 GPU 环境。复制 `tools/personal-executor` 文件夹到个人电脑即可。

Mac 终端：

```sh
sh tools/personal-executor/start-mac.sh \
  --url https://192.168.247.162:18443 --user 你的平台账号 \
  --ca-file deploy/school/node01-dataflow-root-ca.crt
```

Windows 终端：

```bat
tools\personal-executor\start-windows.cmd --url https://192.168.247.162:18443 --user 你的平台账号 --ca-file deploy\school\node01-dataflow-root-ca.crt
```

使用现有平台密码交互登录，不在参数里输入密码。不新增配对码或模型配置文件。`--project 项目ID` 可选择项目，省略时使用当前会话项目，首次登录则选择第一个具有开发权限的项目。CA 文件使用学校已发布的公共证书，不关闭 TLS 验证。

启动后，在平台点击该 Serving 的测试按钮，或者运行绑定它的 Pipeline。默认返回清楚标识的模拟文本，不会访问商业 API；模拟文本仅用于通路测试，不能作为正式训练数据。`--once` 用于只处理一次轮询。真实模式需要显式附加 `--execute`，并将 Serving 的个人执行模式改成真实。`--concurrency 48` 可将执行器同时处理的商业 HTTP 请求上限设为 48，默认仍为 1；对应 Serving 的 `max_workers` 也需配置为目标并发（支持 1–48）。实际并发取决于可用材料单元数量和服务端限制，解析并发独立配置。

## 执行、恢复与边界

请求只允许同一用户在有开发权限的项目内领取；退出、禁用和撤销项目权限由原登录/权限检查生效。一个请求原子领取一次，不因执行器离线自动转给其他用户或学校服务器。领取前检查关联 Pipeline 是否仍在排队或运行，已取消或结束的任务不再发起新请求；已经发到商业服务的在途请求不能撤销。执行器用有界线程池执行商业请求，队列领取和结果回传由单一协调线程串行完成。回传失败时停止新增领取并保留原响应；退出时等待已发出的请求落盘，不自动重复不确定的商业调用。

请求在项目受管数据目录的 `data/personal_calls.sqlite3` 中保存，默认等待五分钟。执行器先把返回结果保存到本机 `~/.dataflow-personal/` 的账号、项目和模式隔离目录，再回传。回传失败时，下次启动先补传原结果，不重新调用商业 API；回传具有幂等校验。未取得响应、已领取后崩溃或超过期限的请求，结果可能未知，不自动重新领取，以免重复收费。过期的未确认结果需人工处理，本版没有跨过期任务自动续跑或完整 Pipeline 断点恢复。

真实调用仅支持公网 HTTPS 的 JSON API，不跟随重定向；继承现有非流式 OpenAI 兼容请求协议。请求超时、失败会通过原 Serving/算子错误处理返回；不新增其他商业 API 后端。个人电脑需同时能访问学校和商业服务。

## 验证与部署范围

自动化测试使用独立临时项目、测试账号、虚构凭据和模拟响应，覆盖原登录与 Serving 测试接口往返、用户隔离、同步/Ray 执行循环、原子领取、结果幂等、模拟/真实队列隔离和断线补传。同步/Ray 循环测试不启动真实 Ray 集群。

Mac 与学校端代码已同步，学校 HTTPS 模拟往返已验证。真实 PDF 与商业 API 验收结果另见运行记录。Mac 本机验证与 Windows 共用标准库实现和启动入口；尚未在真实 Windows 电脑上验收。

学校 PDF 只读查询已检查账号目录及可读共享存储，未找到用户所述八千多篇存档；部分其他用户目录不可读。按用户要求停止扩大搜索，未移动、导入或修改任何服务器 PDF。
