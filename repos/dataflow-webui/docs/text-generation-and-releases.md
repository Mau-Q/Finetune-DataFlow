# 文本任务、训练草稿与发布版本

文中的 `DATAFLOW_WORKSPACE` 指 Finetune-DataFlow 集成仓库根目录；这些集成脚本不属于独立 WebUI 检出。执行前设置该环境变量为实际路径。

当前适用于每位使用者独立运行的单用户 WebUI。入口为「文本生成」和「生成数据集」。

## 配置与提交

1. 在原始数据集中导入所需 PDF。论文模板输入为含 `source` 的 JSONL 材料清单；不直接把训练样本 JSONL 当作 PDF 输入。
2. 打开「文本生成」，选择内置的 13 步论文模板或此前保存的平台文本配置，选择原始数据集。
3. 统一分配文本服务，或在「步骤与必要参数」中分别给清洗、QA 生成与两路评分分配服务。检查 MinerU 脚本、Tokenizer 路径与必要参数。
4. 保存配置，再检查运行条件。没有服务可以保存，但不能提交；缺少模型、端点、凭据或本地依赖路径会有明确提示。检查不会调用远端服务，因此通过检查不证明远端当前可用。
5. 可在「进阶画布」进一步编辑后保存。向导与画布使用同一 Pipeline ID；返回向导时重新读取保存的配置。修改未保存时不能从向导提交。
6. 提交后进入既有 Ray 执行器。保留原来的 13 步、五项评分至少为 4、问题/答案组合去重及 SFT 整理逻辑。没有改为按 PDF 分别运行，批次内筛选与去重语义保持不变。

配置持久化在原 PipelineRegistry。`execution_options` 记录平台执行选项，两种编辑器均保留它。内置模板位于 `backend/app/templates/paper_sft13.json`；脚本与 Tokenizer 默认路径由当前工作区位置补全，也可在向导修改。

## 任务与恢复

- 进度单位为**整批**，同时展示已完成步骤数量。PDF 已解析不表示整批生成完成。
- 提交前复制 PDF 与输入清单，保存 SHA-256；任务中保留 M2 的 Prompt/Schema 内容与哈希，以及不包含密钥的服务配置快照。运行前再次检查输入副本。
- 额外重试默认 0 次，对应核心服务的 `max_retries=1`，即只尝试首次请求。可设置 0–5 次额外重试；原服务的全局设置不修改。
- 失败或取消任务可手动重跑。每次建立新任务与输出目录，保留 `retry_of`、旧失败日志和旧产物。重跑使用固定输入和资源内容；服务配置发生变化时要求从当前配置发起新任务。
- 已完成任务只有在产物仍存在且哈希一致时才能复用；复用返回原任务，不重复执行。0 条通过筛选可正常完成和收集，但空草稿不能发布。
- 应用中断后仍显示 running 的任务，可先终止，再手动整批重跑。当前没有步骤内部、单 QA 或任意断点恢复，也没有自动重启任务调度。
- 任务详情提供日志、失败原因、输入与配置快照、产物清单。原始响应指算子解析前的**模型返回文本**，不包含完整 HTTP 报文。候选文件保存各完成步骤的中间数据；训练产物仅包含 `instruction/input/output`。

同步执行与 Ray 执行共用产物固定与响应捕获逻辑。只有平台任务启用捕获与训练投影；旧任务不会补造历史响应或快照。历史步骤预览只读对应任务、对应步骤的缓存。

## 草稿、发布与导出

1. 任务详情选择明确的目标草稿，点击训练产物的「收集到草稿」。只有完整完成任务的训练产物可收集；候选文件、日志和失败记录不自动进入训练集。
2. 同一任务产物再次收集会报错。相同样本内容跳过新增，同时保留不同来源任务的关联。成员保存稳定样本 ID 和来源任务、产物、文件哈希、原行号。
3. 在生成数据集页预览、编辑或删除样本。文本可直接编辑指令、输入和回答；消息样本通过 JSON 编辑。字段映射将源字段复制到训练字段，原字段保留；整批校验失败不会部分写入。
4. 点击「发布新版本」。校验训练字段、显式图片绑定、图片文件与哈希。固定样本内容、成员、来源与必要媒体，生成版本清单和导出文件。
5. 下载基础 JSONL；符合 `instruction/input/output` 契约的版本另提供对应的精简 JSONL。图文使用「数据与媒体包」ZIP，内含 `data.jsonl`、`manifest.json` 和 `media/` 相对路径文件。
6. 继续编辑草稿会影响下一版本，不改变旧版本。也可从某个版本建立新草稿，其成员与来源继承该版本。图文版本重建草稿目前需要原材料仍通过内容校验；已有版本的下载始终使用发布时的独立媒体副本。

消息与媒体导入沿用 M1 的显式「图片引用 → 材料 ID」映射，绝不按目录中的同名文件猜测图片。发布包中的媒体文件名使用材料 ID，导出时将 `image`、`images` 和消息中的 `image_url` 全部改写为对应相对路径。

## 持久化与备份

- `backend/data/library/task_inputs/`：任务拥有的输入清单与 PDF 副本。
- `backend/cache_local/<task_id>_output/`：任务步骤缓存、解析目录、模型文本与 `artifacts/` 固定产物。
- `backend/data/task_registry.json`：任务元数据与快照；API 与 worker 使用文件锁和原子写入。损坏文件明确失败，不静默重建空历史。
- `backend/data/library/drafts/`：可编辑草稿、成员与来源。
- `backend/data/library/releases/`：独立版本清单、JSONL、ZIP 与文件哈希。元数据是发布提交标志；未成功固定全部文件的版本不列为已发布。

备份应同时覆盖 `backend/data/` 和需要保留的 `backend/cache_local/`；仅备份任务注册表不足以恢复原始响应、产物或输入。复制前停止任务写入，按文件核对哈希。发布版本不依赖原任务缓存继续存在，但任务复用依赖完整产物。

开发验证使用工作区根目录 `${DATAFLOW_WORKSPACE}/scripts/test-local.sh`，前端在 `frontend/` 运行 `npm run build`。离线测试与真实模型调用分别记录；任务完成不代表数据质量已经通过人工或专项验证。
