# 四个代表性 API 数据生成流程

四条流程均不调用模型评分，也不按分数、分差或来源评分淘汰生成结果。
API 配置、数据导入、输出目录选择和真实运行由你在 WebUI 操作；无需本地大模型或 GPU。

## 输入材料

- `text-one.jsonl`：1 条技术说明，建议首先试跑。
- `text.jsonl`：9 条输入，包含 6 份技术说明、1 条精确重复、1 条过短材料和 1 条空白材料。
- `images/`：6 张合成图片，包括表格、统计图和流程图。
- `manual-reference.json`：人工核对依据，不导入 Pipeline。

## 操作

1. 在模型服务中配置 `APILLMServing_request`，API 地址填写完整的 `/chat/completions` 端点。图片流程需要模型支持 `image_url` 内容块及 base64 data URL。
2. 文本通过结构化文件入口导入 JSONL；图片通过图片材料入口导入，取得 `source/material_id` 材料清单。
3. 从模板选择对应流程，在画布选择输入数据集，并为所有 `llm_serving` 绑定服务。
4. 保存为自己的 Pipeline。点击 Save & Run，在运行设置中选择新建数据集（填写名称）或追加到类型匹配的已有数据集，同时选择结果保存目录。首次运行模板时先另存 Pipeline，保存后自动继续进入运行设置。
5. 运行成功后有效样本自动收录到生成数据集，使用运行前选定的新建或追加目标；最终结果面板显示数据集入口。按文本/图文、SFT/DPO 分别记住上次选择，无需生成后手动确认。

已有代表性模板及其保存副本会一次性移除评分节点、评分过滤和偏好排序；保留名称、输入及生成节点的服务绑定。
修改前的配置保存在 `backend/data/backups/removed-training-scoring/`；历史任务及其 Prompt/Schema 快照不会被改写。
旧页面需要刷新，并重新从 Pipeline 列表选择保存的配置，避免用旧画布覆盖新版。

## 四条流程

| 流程 | 总步骤 | 模型节点 |
|---|---:|---:|
| 文本 SFT | 8 | 1 |
| 文本 DPO | 11 | 2 |
| 图片 SFT | 5 | 2 |
| 图片 DPO | 8 | 3 |

文本 SFT：输入结构过滤 → 来源去重 → 保留原文 → 规范空白 → 多跳 QA 生成 → QA 展开 → 样本去重 → SFT 整理。

文本 DPO：在多跳 QA 问题与正例回答的基础上，生成同题合成负例 → 检查同题并组合 A/B → 将正例写入 chosen、合成负例写入 rejected → 去重 → DPO 整理。

图片 SFT：来源去重 → 看图生成问题 → 看图生成回答 → 样本去重 → SFT 整理。

图片 DPO：来源去重 → 看图生成问题 → 看图生成正例 → 看图生成合成负例 → 检查同题并组合 A/B → 整理 chosen/rejected → 去重 → DPO 整理。

DPO 的负例由提示词要求产生一个明确的事实、计算或关键条件错误。偏好来自合成角色，未经独立评价；任务配置的 `preference_policy` 和中间行的 `preference_basis` 记录为 `synthetic_positive_negative`。不能将这些样本描述为经过模型判优、人工核验或已证明具有训练收益的数据。

仍保留清洗、精确去重、同题检查、非空字段及 JSON/训练结构校验。结构错误会明确报错；不再因模型打低分而丢弃回答。过短、空白或重复输入仍可能被输入规则剔除，空输入仍可正常导出 0 条。

## 输出与核对

文本 SFT 输出 `instruction/input/output`，文本 DPO 输出 `prompt/chosen/rejected`；图片分别输出 `messages/images` 和 `prompt/chosen/rejected/images`。

`text-one.jsonl` 最多输出 1 条；完整文本输入规则过滤并去重后最多 6 条；6 张图片最多输出 6 条。无重试时，完整文本 SFT 约 6 次模型请求，文本 DPO 约 12 次，图片 SFT 12 次，图片 DPO 18 次。

每次运行单独创建目录，包含 `final.jsonl`、`manifest.json`、日志、每步中间结果和模型响应；图片任务附可读取的图片副本。成功且非空的有效训练结果由后端自动收录到生成数据集；重复完成回调不会重复入库。空结果、不符合训练结构的结果不入库，原因显示在最终结果面板；数据库写入失败会单独提示，原生成文件保留。后续编辑不会反向改变运行产物。

本地测试使用隔离材料和模拟模型响应，覆盖四条流程、独立 worker、无评分丢弃、空输入、协议错误及迁移。真实 API 兼容性和样本内容由真实运行验收。

## 单条失败与负例重试

四类流程逐条隔离无效候选，最终文件只包含有效训练样本；`invalid_samples.jsonl` 保留无效行、来源和失败原因，页面显示有效/无效数量及下载入口。全部无效时保留空最终文件和错误明细，不创建空生成数据集。缺失字段、服务配置错误等流程配置问题仍会中止提交或执行。

文本和图片 DPO 配对时检查正负回答是否相同（包含纯数字与相同数字加单位的简单形式变化）。使用原生成服务，最多额外生成负例 2 次；文本重试附带原文，图片重试附带原图。重试原始响应保留在中间结果和响应产物中；达到上限仍无效时只隔离该行，不影响其他样本。该检查不等同于语义判优或质量评分。

已有四类模板及保存副本会一次性迁移，修改前配置在 `backend/data/backups/training-row-isolation/`。历史任务与历史结果不修改；刷新页面后重新选择流程再运行。
