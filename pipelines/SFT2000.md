# 原 2000 条基线：DataFlow 接入

WebUI 中选择 **Pipeline → 自定义 Pipeline → 旧 2000 基线 · Qwen 生成 → DeepSeek 审核 → SFT 导出（3 条联调）**。

```text
三条冻结证据 evidence_record
  → SFT2000Generator   generation_result：原生成响应、实际模型、长度校验
  → SFT2000Verifier    verification_result：原独立审核、逐声明证据判定
  → SFT2000Exporter   export_status：PASS 导出，保留其余审计
```

已保存的后端配置为 [sft2000.json](sft2000.json)，注册信息为 [sft2000.registration.json](sft2000.registration.json)。可以在 UI 查看参数与切换服务，也可以从后端创建、执行；不要求手工拖拽。Pipeline 只存 Serving ID，密钥仍由服务管理保存。

## 与历史配置对齐的部分

| 项目 | 当前实现 |
| --- | --- |
| 生成 | qwen3.7-plus，temperature=0.2，enable_thinking=false，max_tokens=2048，JSON object |
| 生成提示词 | paper_sft_answer_only_zh_v3 |
| 独立审核 | deepseek-v4-pro，temperature=0，thinking=disabled，max_tokens=3200，JSON object |
| 审核提示词 | paper_sft_claim_verifier_zh_v3_2_5 |
| 长度 | question + evidence + answer 最多 400 混合单位；旧聊天模板渲染后最多 4096 tokens |
| Tokenizer | Qwen/Qwen3.6-27B，revision 6a9e13bd6fc8f0983b9b99948120bc37f49c13e9，三个文件按冻结 SHA-256 校验 |
| 导出 | 仅 PASS；每篇最多 3 条；规范化问题精确去重；instruction/input/output |
| 失败处理 | 保留 SKIP、REJECT、REVIEW_REQUIRED、协议/身份/请求错误；不自动重写或语义重试 |
| 请求 | 复用旧 HTTP gateway：生成 timeout=60 秒且无传输重试；审核 timeout=120 秒且最多一次传输重试 |

纯提示词、判定、token 计数、生产去重和导出函数从退役代码中按原文提取，位于 `extensions/paper-dataflow/paper_dataflow/baseline/`。`vendor_manifest.json` 保存源路径、源哈希、符号、行区间与本地文件哈希。运行时不导入旧项目，不读取旧项目密钥。

DataFlow 的 Serving 在此提供当前 UI 中的端点和密钥；算子严格核对模型、温度、输出上限、思考开关、超时和尝试次数，然后调用旧 gateway。旧 gateway 使用同一标量 timeout，不使用 DataFlow 的 `(connect_timeout, read_timeout)` 元组。日志保存实际模型和原始响应，模型身份不符不进入 PASS。

## 当前输入和对照边界

- `data/sft2000/evidence-smoke3.jsonl`：按归档顺序选取不同论文的前三条证据，仅包含证据和来源元数据，不包含旧问题/答案/审核结果。
- `data/sft2000/evidence-2000.jsonl`：2000 条历史通过记录对应的原始证据，895 篇论文。保留证据原文与原规范化哈希，另外记录原文字节哈希。
- `data/sft2000/txt1199-source-catalog.jsonl`：1199 篇 TXT 的原始文本、ZIP 成员名及哈希。它是来源目录，未重新分块，也不是已冻结的实验候选队列。
- `data/sft2000/manifest.json`：归档三份资产、来源 ZIP 和生成数据集的 SHA-256。

默认 `max_records=3`，整个输入批次会先检查条数、证据哈希、train 标签和候选 ID 重复，再调用模型。每次运行串行处理。历史生产最大并发为 48；当前 Qwen 使用用户新填的平台端点，与旧 DashScope 域名不同。因此这是一条沿用旧算法配置的联调流水线，不是历史运行环境的完全复现。

这批输入来自历史被接受的 2000 条记录，带有选择偏差。离线回放证明迁移一致性，三条真实调用证明接口与流水线接通；两者都不证明新流程的总体质量、通过率或训练收益。正式对照需另行固定完整候选输入、划分、变量与评价集。不能把重新分块后的 TXT 直接当作原候选队列，也不能把这 2000 条 train 记录当独立测试集。

在 DataFlow 根目录执行：

```sh
# 只验证及注册，不调用模型
.venvs/dataflow/bin/python scripts/register-sft2000-pipeline.py

# 离线回放历史响应，不调用模型
.venvs/dataflow/bin/python scripts/replay-sft2000.py

# 离线契约测试
.venvs/dataflow/bin/python -m unittest discover \
  -s extensions/paper-dataflow/test -p 'test_*.py' -v
```

点击 UI 的 **Save & Run** 会使用当前输入重新调用模型。默认是三条；每次点击都是新的运行，不复用旧响应。不要为了运行参考集而直接把上限改到 2000。

模型请求证据保存在 `outputs/sft2000-runs/<run-id>/`；导出保存在 `outputs/sft2000-exports/<export-id>/`。每次独立目录包含 `sft.jsonl`、`audit.jsonl`、`record_mapping.jsonl`、`summary.json`。`sft.jsonl` 是训练格式；`audit.jsonl` 保留全部输入和失败结果；中间 DataFlow 表保留完整字段供 UI 查看。

已有 PDF → MinerU → 分块流程独立保留，见 [README.md](README.md)。它用 Qwen2.5 tokenizer 做准备阶段分块，不能替代这里的 Qwen3.6 最终长度检查。TXT 没有 PDF 物理页码和坐标，未添加虚构定位字段。
