## 2. 基线事实与插入位置

```text
论文证据 → 原生成器 → 格式/400 混合单位/4096 token 校验
                     → 原逐声明审核 → PASS
                     → 每论文最多 3 条 / 规范化问题精确去重 → 原 SFT 导出
                                                                ├─ E1：近似重复候选诊断
                                                                └─ E2：附加质量评分与选择诊断
```

首轮从最终导出的 B 数据分叉，两项不串联、不回填、不补齐被选择掉的数量，避免改变原 cap 和去重顺序而引入额外变量。两项都只能改善交付集合的选择，不能修复已生成答案，也不能增加绝对合格样本数。将来若把算子移到生成前以节省调用费，必须单独对照。

B 仍使用原提示词及审核机制；本轮不采用后续其他研究中的提示词版本。映射为 `instruction=question`、`input=原 evidence`、`output=answer`。保存 `candidate_id`、`paper_id`、证据及响应哈希和原行序；禁止只凭行号跨过滤步骤关联。

本地最新三条联调记录为 1 PASS、2 REVIEW_REQUIRED，后者包含 evidence point / obligation / claim ambiguous 原因。该样本不足以推断总体错误分布，也没有提供“重复很多”或“质量评分有效”的证据。历史 2000 条是已被原流程接受的样本，只能用于接口与回顾性诊断；1199 篇 TXT 目录不是已冻结的完整候选队列。

## 3. 逐项候选表

成本列指每条进入该阶段的数据；LLM 的逻辑调用数不等于 HTTP 批次数，实际 tokens、失败和重试均应计费。默认值来自实时 MCP，算法行为来自源码。

| **MinHashDeduplicateFilter** | 单列文本或多列拼接；字符 n-gram MinHash/LSH；默认 128 permutations、5-gram、threshold=0.9；按输入顺序保留命中前的代表 | CPU、datasketch；0 次 LLM；本机依赖存在，真实算子已小样本运行 | 字面近似，不是语义判同；原生只保存保留行，没有重复配对理由；`input_keys` 单元素路径不能当作单列入口，使用 `input_key`；相似度阈值不构成精确 Jaccard 保证 | **E1：优先，作为重复候选诊断** |
| **AlpagasusSampleEvaluator / Filter** | 读取 instruction、input、output；官方 quality 提示词要求 0–5 分；Filter 默认保留 3–5 | 可接 LLM Serving；每条约 1 次评分调用；无需新的本地评分权重 | 可以将论文证据传入 input，但原提示词不是逐声明证据审核；只保留数值，不保存评语；首行首 token 转 float，无健壮容错及范围检查；先用 Evaluator 留全量分数 | **E2：优先，旁路评分，不替代审核** |

| **DeitaComplexityFilter** | 实际推理只输入 instruction，虽接口还读取 output 列；预测 1–6 复杂度 | hkust-nlp/deita-complexity-scorer；本地生成；默认 cuda | 复杂度不是回答正确性或训练价值；max_length 同样是生成上限；不能用于证明证据支持或答案完整 | 后续难度分布研究候选 |

官方 SFT 合成参照仍是 `SFTGeneratorSeed`：从文档生成一条 instruction/output，支持 custom_prompt。它用于 A/B 方法比较，不是本表的 B 增强组件。其输出重建 DataFrame，不自动保留全部输入元数据；正式比较前必须补可核验来源映射和失败记录。不得把缺失行从输入分母排除。

### 3.1 质量优先的排序与 E1-S 语义去重验证

实现存在缺口不等于方法不值得研究。允许小范围修正或替换后测量，但应区分原生实现与适配版本，记录一次性开发、模型获取、每批运行及人工核查的全部成本。若修复成本小而质量收益明确，可以优先采用适配版本；Deita、改写等候选也遵循同一原则，不能仅因需要模型或多次调用而长期排除。

语义去重与 MinHash 的价值不同：前者有机会发现措辞不同但信息重复的 QA，后者主要发现字面近似。语义去重也可能混淆同主题、不同结论的样本；最终评价单位是包含来源条件的 QA 信息，而非向量分数。共享相同问答却适用不同论文条件的记录不能自动合并。

E1-S 在正式筛选之前进行，作为 E1 的方法候选比较，不叠加在 MinHash 后面：

1. 从开发池取最多 200 条 QA，保存原证据及 ID；独立补充数字、否定、条件不同的压力对。自然样本和合成样例分别报告。此规模只验证可行性，不证明全库增益。
2. 先核对现有模型资源和中文能力，再选定一个嵌入模型。用固定模型测试同一句话单独编码、与长短句混合编码时的向量一致性，检查 attention mask、截断、实际 eval 状态。比较原生实现与最小修正实现，避免把换模型和改池化的贡献混在一起。若另换中文模型，单列适配方案。
3. 全量矩阵不是小规模实验的否决理由：2000×2000 的 float32 相似度矩阵本身约 16 MB；这不包含模型权重、编码激活、拷贝和其他中间张量。先测分批编码与实际峰值内存、耗时，再决定是否需要分块相似度；没有规模证据时不预先开发复杂索引。
4. 与原精确去重、MinHash 在同一 QA 池上比较。人工核验两法独有和共同触发的配对，并补随机负例及困难反例；报告各层抽样量。要比较召回率，应使用人工完备标注的小池，不能只审查已触发配对。模型和阈值在开发集选择，确认集不得再调。
5. 主要收益：保留关键事实及条件的前提下，减少真实冗余、保留更多独立知识。代价：错误合并、遗漏、推理与人工核查成本。相似度更高、删除更多、重复率更低都不能单独证明 SFT 质量提升。

共同采用原则：先检查事实支持、完整性和关键条件保留，再比较数据集覆盖、重复、有效样本保留率及每条有效独立样本成本。允许单项指标的明确取舍，但不使用未确认的综合分数掩盖事实质量下降。下游训练收益仍需另行训练对照才能成立。

## 4. E1：现有精确去重之后，近似去重还有多少价值

### 假设与输入

假设：B 的问题精确去重后仍有字面近似且信息等价的 QA；MinHash 能以可接受的误报代价发现它们。先验证重复是否真实存在，不能预设收益。

先使用只读历史导出副本做回顾性诊断，覆盖全部 2000 条而不是只看前三条；身份先比对现有 manifest。该结果只代表这个历史接受集合。正式确认使用新实验中 B 的完整导出池，按论文划分开发/确认，跨分区不联合去重。每个池内部保留真实重复，不为凑样本预先去重或挑重复。

### 单一变化与参数

- 原对照：B 的导出集合原样保留。
- 候选：同一集合增加 MinHash；构造 `qa_text = instruction + '\n' + output`，固定拼接规则与原行序。不拼接长 evidence，以免相同证据掩盖不同问答；原文留给人工核对。
- 开发起点：num_perm=128、ngram=5、threshold=0.9、use_n_gram=True，均沿用原生默认，不提前搜索大量阈值。
- 使用原生算子的保留/丢弃 ID 定义候选行为；另存输入全量及按同一 LSH 查询产生的代表候选 ID、字符 n-gram Jaccard、数值差异，便于解释。后者是审计适配，不得暗中改变筛选结果。
- 初轮只输出“建议重复”标签。无论分数多高，数字、对象、条件、否定、范围不同都不能直接认定信息等价。

### 人工核验与对照

开发诊断：自然触发对最多抽 60 对；不足就全查并报告不足，不制造自然重复。另抽 60 对未触发候选作为误漏诊断，其中随机对和专门选择的困难近邻分别报告。合成的数值/否定反例独立列为压力样例，不混入自然重复率。

对每对标记：完全重复 / 可安全合并的改写 / 同主题但不同信息 / 冲突信息 / 无关，并保留依据。随机负例不足以估计全库召回率；若需召回率，应另构建人工完备标注的小型对照池。

报告：候选触发率、人工确认的可合并比例、错误合并数、重要条件/数字丢失数、保留量、人工审核时间和 CPU 耗时。若模拟删除，比较同保留条数的随机选择（固定若干随机种子）及原集合，报告独立信息保留量，不能只报重复率下降。

继续条件：真实池存在有意义的冗余、审查成本与可减少冗余相称，且没有关键事实误合并。发现关键事实误合并时，不启用自动删除；结果可支持“用于提示人工检查”。重复很少则停止该方向，不继续调参以追求删除数。

已知压力结果：默认配置会将只有 85%→65% 区别的合成文本当成重复删除。因此当前没有将原生 MinHash 直接加入生产过滤的依据。

## 5. E2：原审核之后，通用质量评分是否提供额外信息

### 假设与插入位置

假设：B 审核并导出后，仍存在表达、问题价值或完整性差异；Alpagasus 的质量分数可以改善人工复核排序，或在固定交付名额下选出更好的数据。它不提升原已生成池的绝对好样本数，也不负责放行原 REJECT/REVIEW_REQUIRED。

对同一批 B 导出 QA 旁路运行 `AlpagasusSampleEvaluator(dimension='quality')`，绑定 instruction/input/output，其中 input 就是原证据。保留官方提示词，不加入旧审核 rubric。原 PASS 不是人工正确标签；由独立人工判断才可评价新增评分。

### 开发与确认

- 首轮开发诊断拟用最多 30 条，每篇最多 3 条，至少覆盖 10 篇（不足则如实记录）。这是新 B 导出池中的样本，不通过看分数选样。
- 若有分辨力，再使用不同论文的确认池，目标 60 条，至少 20 篇；这是目标 QA 数，不能假设 60 个证据一定产生 60 条 PASS。若缺少足够自然样本，不为凑齐而无限追加生成。
- 历史 2000 条可先用于接口回放/回顾性评分，但必须单列，不得冒充新确认池。当前 1 条新 PASS 不足以进行该实验。
- 主比较：全量 B；按分数保留预先约定的前 80%；同样数量的随机保留。并列分数按固定 candidate_id 排序，记录并列率；随机基线建议种子 0–19，20 次离线抽样，不产生新模型调用。
- 80% 是待确认的诊断工作点，不是已冻结采用标准。只能在开发阶段改动；进入确认前固定阈值/保留比例与主指标。默认 Filter 的 3–5 阈值仅作描述性参考，不另做择优汇报。

### 实际请求与失败处理

评分模型拟沿用当前审核角色的模型，以避免增加新模型因素；这只定义方案，未创建或修改服务。需要单独评分配置：原审核 response_format=json_object 与 Alpagasus 的首行数字协议冲突，不能直接复用原 Serving 配置。保持端点/实际模型可追踪、temperature=0、关闭思考；拟输出上限 1024、单并发、无重试。运行前核对模型能力与实际配置。

开发评分最多 30 次逻辑请求，确认最多 60 次；基线生成和审核成本另计，不能称总实验仅 90 次。货币硬上限尚未填写，不伪造价格；运行前按实际 token 单价与输入长度核算。不得由本草案自动启动付费调用。

原生解析器只取首行首词转 float：`Score: 4` 会 ValueError，`6` 会被接受。实验侧必须保存原响应/评语，区分协议错误、超范围、请求失败和有效分数；不静默转为 0、不自动重试以刷出合法分数。对协议失败项保留原 B 状态并单独列出，不纳入有效分数排名；名额与比例以有效分数子集计算，同时报告全量覆盖率。实现若添加容错，应标明适配，不能声称原生无修改。

### 评价与继续条件

人工先看问题、答案、原文，隐藏评分和旧 PASS；分别标注事实支持、完整性、问题价值、表达清楚程度。样本短或简单不自动判低质，长答案也不自动判高质。Agent 评价可作为辅助，不代替用户/独立评审的标签。

报告：同交付名额的人工合格率、关键事实错误数、好样本保留率、按问题类型的覆盖、与随机选择的差值；另报所有失败、分数分布及并列率、增量 tokens/费用/耗时、每条合格交付的总成本。过滤后合格率提高但丢掉大量好样本或覆盖收缩，必须同时展示。

继续条件：在独立池中，质量选择或人工复核排序出现实用增益，且收益能解释增量成本；分数几乎全相同、与人工判断不一致或不优于同数量随机选择时停止。小样本差值不宣称统计显著或训练收益；若后续扩大，按论文而非单条 QA 处理相关性。

## 6. 执行顺序与当前缺口

1. 已完成：源码、实时 MCP 签名与依赖可发现性核查；MinHash 合成压力样例与 Alpagasus 模拟响应检查；无模型下载和付费调用。
2. 下一步：E1 历史副本只读诊断，并安排 E1-S 语义去重的小规模资源/实现核验，共用配对审查标准。先确认语义方法的实现代价与额外发现能力，不因默认实现缺口直接排除。不得回写历史数据。
3. 并行研究主线仍保留官方 SFT 方法 A 与 B 的同源生成对照；本草案不替代其输入冻结工作。
4. 在新 B 样本形成后做 E2 开发评分；还缺独立候选池、最终评分配置、货币预算及人工标签。不要仅因一条联调 PASS 直接扩到全量评分。
5. 两项独立有价值后才设计组合；本轮不预设组合优于单项，也不启动训练。
